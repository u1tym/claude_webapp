# 画面の見た目、共通の画面分割とナビ

> 元Cursorルールでの適用範囲: `specs/**/ui-design.md`、`src/features/**/frontend/**/*.{vue,css,scss,ts}` を編集するとき。コンテンツの部品は各機能の `ui-design.md` で決める。

他機能の SPEC・Vue・CSS・コンポーネントを参照・import しない。既存コンポーネントの再利用はしない。
見た目の正は本ルールである。他機能の画面・コードは見ない。
色・余白・部品の見た目はこのルールに合わせ、各機能の `frontend/` に同じ値を置く（`--color-primary` だけ機能ごとにパレットから 1 つ選ぶ）。ナビも各機能の `frontend/` に、このルールの見た目と形で実装する。

**このルールが決めること:** 色・余白・部品の見た目、画面の分割（ヘッダ / ナビ / コンテンツ）、ナビの形。
**各機能の `ui-design.md` が決めること:** コンテンツ領域に何を置くか、画面間の遷移先。同じ役割のものは、既存と同じ見た目と思想で設計する。

**殻の対象外:** ログイン画面とメニュー画面。ヘッダ / ナビの殻は使わない。部品配置は当該機能の `ui-design.md` に従う。色・余白・部品の見た目のトークンは本ルールに合わせる。


## 前提

- ページ全体はスクロールさせない。部品内のスクロールは可。
- 対象: PC とスマートフォン。
- 想定ブラウザ: Google Chrome、Safari。
- ブレークポイント: **768px 未満をスマートフォン**。
- 余白は `--space`（8px）の 1〜4 倍（8 / 16 / 24 / 32px）のみ。画面内余白は 24px。タップ領域は `--tap`（44px）。


## 思想

情報を主役とする。明るく柔らかな面の上に、淡いパステルの色面と一つのアクセントで構造を示す。視認性・操作性・拡張性を優先する。

キーワード: Precise / Bright / Gentle / Structured / Extensible

常に意識すること

- 学習コストが低い
- 情報を探しやすい
- 操作ミスしにくい
- 機能追加時も見た目が破綻しない

同じ役割のものは必ず同じ見た目とする。機能ごとに専用の見た目を作らない。殻（分割とナビ）は、ログイン画面とメニュー画面を除き、全機能で同じ形にする。

避けること: 高彩度の蛍光色の塗りつぶし、虹色のグラデーション、厚いドロップシャドウ、目的のないアニメーション、コントラストの低い配色（淡い文字色を淡い背景に重ねる等）。

優先すること: 可読性、視線誘導、情報密度の最適化。明るい背景でのコントラスト。

新機能は既存コンポーネントを再利用しない。このルールの見た目・思想・殻へ適合させる。新しい見た目パターンは、既存では表現できないときだけ追加する。


## 画面分割とナビ

ログイン画面とメニュー画面は、この節の殻を使わない。

それ以外で画面がある機能は、次の殻を使う。中身（コンテンツ）は機能の要件に合わせる。

### PC（768px 以上）

```
┌──────────────────────────────┐
│ Header                       │
├────────┬─────────────────────┤
│ Nav    │ Content             │
└────────┴─────────────────────┘
```

- ヘッダは上端に置く。
- ナビは左に固定し、常時表示する。アイコンとラベルを並べ、現在地を明確にする。階層は浅く保つ。
- コンテンツ領域を最大化する。複数カラムにしてよい。
- 一覧と詳細の両方があるとき、同時表示してよい。

### スマートフォン（768px 未満）

```
┌─────────────────┐
│ Header          │
├─────────────────┤
│ Content         │
├─────────────────┤
│ Bottom Nav      │
└─────────────────┘
```

- ヘッダは上端に置く。
- ナビは下端に固定する。主要機能だけ、項目数は最小限。片手操作を前提にする。
- コンテンツは単一カラム。ページ全体はスクロールさせない（部品内のスクロールは可）。
- 一覧と詳細は同時表示しない。画面遷移で分ける。

トークン（色・余白・字サイズ・角丸・タップ領域）は PC / スマートフォンで変えない。サイズと情報密度はスマートフォンで下げてよい。


## トークン

各機能の CSS に同じ変数を定義する（他機能から import しない）。`--color-primary` 以外の色・角丸・フォントは機能独自の値にしない。

```css
:root {
  --color-bg: #faf7f2;
  --color-surface: #ffffff;
  --color-text: #3a3244;
  --color-text-muted: #8b8496;
  --color-border: #e6e0ed;
  --color-primary: #4ecdc4;
  --color-danger: #d1477a;
  --space: 8px;
  --radius: 8px;
  --font-size: 16px;
  --font-size-title: 20px;
  --tap: 44px;
  --duration: 200ms;
}
```

`--color-primary` は次から機能ごとに 1 つ選ぶ。画面全体の背景には使わない。パレット外の独自色は置かない。彩度を上げすぎた蛍光色にはしない（淡く柔らかいトーンを保つ）。

```
Teal     #4ECDC4
Blue     #6C9BFF
Violet   #A78BFA
Lime     #A0D468
Orange   #FFA36C
Magenta  #E58FE0
Amber    #F2C94C
```

テーマカラーを使う箇所

- ナビ: 選択中、アイコン、アクティブインジケータ
- ヘッダ: 下端の 1px ライン、タイトルの補助
- カード: 枠、ホバー時の淡い光
- 主ボタン
- フォーカスリング
- チャートの系列

ページ背景は `--color-bg`。薄いグリッド（アクセントの 4% 程度）を敷いてよい。パネルは `--color-surface`。フォントはシステム UI。本文 16px、見出し 20px。アニメーションは 150〜250ms（既定 `--duration`）。強調はフォーカス・選択・ホバーに限り、常時点灯の強い光彩は使わない。


## 情報の優先度（見た目）

画面内は次の順で識別できるようにする。色や装飾より、字の大きさ・濃さで階層を付ける。

1. Primary: タイトル、主要コンテンツ、主要アクション
2. Secondary: 状態、分類、ラベル、カテゴリ
3. Tertiary: 更新日時、作成日時、メタ情報

見出し階層: Page Title / Section Title / Body / Caption。


## 部品の見た目

同じ役割の部品は次の見た目にする。呼び方は揃える。コンテンツに置くかどうかは `ui-design.md` で決める。ヘッダとナビは殻として置く。

| 部品 | 見た目 |
|------|--------|
| 見出し | 20px、`--color-text` |
| 説明文 / Caption | 16px または一段小さく、`--color-text-muted` |
| 主ボタン | 塗り `--color-primary`、高さ `--tap`、角丸 `--radius`。文字は `--color-text` |
| 副ボタン | 面 `--color-surface`、枠 `--color-border`、文字 `--color-text`、高さ `--tap`、角丸 `--radius` |
| テキストボタン | 枠なし、文字 `--color-text-muted` または `--color-primary`、高さ `--tap` |
| カード | 面 `--color-surface`、枠 1px `--color-border`、角丸 `--radius`。ホバー時だけ枠を `--color-primary` に近づける |
| 入力 | 面 `--color-surface`、枠 `--color-border`、文字 `--color-text`。フォーカス時は枠 `--color-primary` |
| 一覧 | ヘッダ行は固定、本体だけスクロール。行の枠は `--color-border`。行内の横スクロールはしない |
| ヘッダ | 上端。面 `--color-surface`。下端 1px は `--color-primary` |
| ナビ | PC は左固定、スマートフォンは下端固定。選択中は `--color-primary` |

大きなドロップシャドウは使わない。階層は面の明るさと枠で示す。


## アイコン

ボタンはアイコンのみとする（文字ラベルは置かない）。意味は `aria-label` で示す。対応するアイコンが無い操作、または近接する複数のボタンが同じアイコンになって区別できなくなる操作は、その操作だけ文字ラベルのボタンのままにする。

- アイコン素材はリポジトリ直下の `icons/`（単色 SVG、`fill` は `#4B4B4B` 固定）を元にする。他機能のコンポーネントは import しないため、各機能の `frontend/src/components/Icon.vue` に、使う分だけ `fill="currentColor"` に置き換えて複製する（`icons/` の SVG をそのまま `<img>` で参照しない。`currentColor` で枠・文字色を継承できなくなるため）。
- 表示サイズは 20×20px（`.icon` クラス）。ボタン自体の高さ・幅は `--tap` を維持する。
- 色はボタンの文字色をそのまま継承する（`--color-text`、テキストボタンなら `--color-text-muted`、破壊的操作なら `--color-danger`）。アイコン専用の色は作らない。
- 一覧の行選択ボタン（行を押して対象を選ぶもの）はアイコン化の対象外。表示しているデータ（タイトルなど）がラベルを兼ねる。


## モーダル / ダイアログ

背景（オーバーレイ）をクリックしてもダイアログを閉じない。閉じる操作は、ダイアログ内の明示的なボタン（キャンセル・閉じる・保存など）からだけ行う。誤操作による入力破棄を防ぐため。


## 状態の見た目

| 状態 | 見た目 |
|------|--------|
| 読込中 | 領域の中央に「読み込み中…」。操作は無効 |
| 空 | 本体に「データがありません」 |
| エラー | 対象領域の先頭にエラーメッセージ（`--color-danger`）。操作は可能なら維持 |
| 成功 | 対象領域の先頭に成功メッセージ。数秒で消してよい |


## 文言

同じ意味の操作は、次の語を優先する。機能固有の動詞は `ui-design.md` に書いてよい。ボタンはアイコンのみのため、これらの語は `aria-label` として使う（画面上の可視文字としては出さない）。

保存、キャンセル、戻る、削除、新規、編集、確定、閉じる、検索。


## アクセシビリティ

必須: 十分なコントラスト、キーボード操作、フォーカス表示（`--color-primary` の枠）。タップ領域は 44px × 44px 以上。アイコンのみのボタンは、必ず `aria-label` で操作の意味を持たせる。
