# ログ出力

> 元Cursorルールでの適用範囲: 常時適用（契機・区分・ローテーションの基本方針）

バックエンドがファイルへ出す記録の方針。画面への表示内容とは別である。

## 出力先

- 機能ごとのバックエンドは、自機能の `backend/log/` へ出力する。
- ファイルサイズでローテーションする。上限サイズと世代数は、その機能の `backend/.env` で持つ（`LOG_MAX_BYTES`、`LOG_BACKUP_COUNT`）。
- ログファイルはリポジトリに含めない。

## 1行の内容

タイムスタンプ、区分、メッセージをこの順で出す。

区分は次のいずれかとする。

- **INF**: 正常な処理の進行（入力の受付、判断が成功したこと）
- **WRN**: 想定内だが正常系ではない（認証失敗、入力不正、対象なし）
- **ERR**: 想定外の失敗（未処理例外、外部障害）
- **DBG**: 調査用の詳細。本番では出さなくてよい

## 契機

次を契機として出力する。省略しない。

- **入力された内容**（受け取った値のうち、判断に使うもの）
- **それを元にした判断結果**（許可した／拒否した、成功／失敗など）
- **正常系ではない場合の理由**（画面へ出さない内部理由も含める）

```
# ❌ BAD: 結果だけ
2026-08-26 22:00:00 INF ログインしました

# ✅ GOOD: 入力・判断・（失敗なら）理由
2026-08-26 22:00:00 INF ログイン要求 username=alice
2026-08-26 22:00:00 INF ログイン成功 username=alice
2026-08-26 22:00:01 WRN ログイン失敗 username=bob 理由=パスワード不一致
```

## 秘密情報

パスワード、セッション ID、Cookie の値、API キー（キー全体とそのハッシュ）はログに出さない。API キーを識別するときは、識別用の先頭部分だけを出す。
