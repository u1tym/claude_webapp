# DB設計作成（日本語）

> 元Cursorルールでの適用範囲: `specs/**/db-design.md` を編集するとき。ER図とテーブル設計

見出しと本文は日本語で書くこと。

`specs/templates/db-design-template.md` に従うこと。

テーブルが無い場合は「テーブルなし」と書き、ER 図とテーブル設計も「なし」と明記すること。ファイルは省略しない。

テーブルがある場合:

- **ER 図**を書くこと。Markdown 内は mermaid の `erDiagram` を使う。
- **テーブル設計**をテーブルごとに書くこと。含める項目:
  - スキーマ名とテーブル名
  - 目的
  - カラム（名前、型、NULL、既定値、説明）
  - 主キー・一意制約・外部キー
  - インデックス

API のパスや画面の詳細は書かないこと（それらは `api-design.md` / `ui-design.md`）。

要件に存在しないテーブルや列を追加しないこと。

機能ディレクトリが kebab-case の場合、スキーマ名は snake_case（例: `order-history` → `order_history`）。
機能固有テーブルは機能スキーマに置く。
`public` に置いてよいのは、ユーザ、セッション、システム設定、機能マスタ、メニュー割当だけである。`public` に業務テーブルを増やさない。
ユーザ・セッション・機能マスタ・メニュー割当を機能スキーマに複製しない。

ユーザが `ui-design.md` を承認するまで、このファイルを作成しないこと。
ユーザがこのファイルを承認するまで、`api-design.md` を作成しないこと。

承認欄は履歴形式とする（日時・状態・変更概要。詳細は `CLAUDE.md`）。
