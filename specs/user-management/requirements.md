# 機能: user-management（ユーザ管理）

## 目的

運用者が Web 画面から、ユーザと機能の登録・更新・削除と、ユーザへの機能の割当を行えるようにする。ログインとメニューは `portal` が担い、本機能は同じ共通データを更新する。

## ユーザーストーリー

- 運用者として、画面からユーザを追加・更新・削除したい。なぜなら、コマンドを使わずに利用者を整えたいから。
- 運用者として、ユーザのメールアドレスを登録・変更したい。なぜなら、連絡先をユーザ情報として持っておきたいから。
- 運用者として、画面から機能を追加・更新・削除したい。なぜなら、メニューに載せる機能を画面で整えたいから。
- 運用者として、ユーザへ機能を割り当て、また外したい。なぜなら、誰がどの機能を使えるかを画面で変えたいから。

## 用語

| 用語 | 意味 |
|------|------|
| ユーザ | ユーザ名とパスワードとメールアドレスで識別される利用者。`portal` と同じ共通データである。ログインに使うのはユーザ名とパスワードである。 |
| 機能 | 識別子、タイトル、遷移先、アイコンを持つ業務機能。`portal` と同じ共通データである。 |
| 割当 | あるユーザのメニューに、ある機能を載せる関係。表示順を持つ。 |
| 論理削除 | データを残したまま、以降の認証・表示・割当の対象外とすること。 |
| 本機能 | このユーザ管理機能そのもの。メニューへ載せる機能の一つである。 |
| ログ | 操作の入力、判断結果、正常系ではない場合の理由を、タイムスタンプと区分付きで残す記録。画面へ出す文言とは別である。 |

## 要件

要件は EARS の意味を保ち、日本語の文で書く。画面部品、テーブル定義、API パス、HTTP ステータスなど設計は書かない。

### REQ-001

本機能を利用するとき、システムはログインを必須とし、ログイン中ユーザに本機能が割り当てられているときだけ利用を許可すること。

#### 受け入れ条件

- [ ] 未ログインでは、ユーザ・機能・割当を操作できない。
- [ ] 本機能が割り当てられていないログイン中ユーザは、操作できない。
- [ ] 論理削除済みのユーザまたは本機能では、操作できない。
- [ ] 判定は他機能の API に依存しない。

### REQ-002

ログイン中の、本機能が割り当てられた利用者がユーザ一覧を要求したとき、システムは削除されていないユーザを示すこと。

#### 受け入れ条件

- [ ] ユーザ名が一覧に出る。
- [ ] メールアドレスが一覧に出る。
- [ ] 論理削除済みのユーザは出ない。
- [ ] パスワードは一覧に出ない。

### REQ-003

ログイン中の、本機能が割り当てられた利用者がユーザを追加するとき、システムはユーザ名とパスワードとメールアドレスでユーザを追加すること。

#### 受け入れ条件

- [ ] ユーザ名とパスワードとメールアドレスを指定して追加できる。
- [ ] ユーザ名、パスワード、メールアドレスが空のときは追加できない。
- [ ] メールアドレスの形式が不正なときは追加できない。
- [ ] 同じユーザ名のユーザを複数登録できない。
- [ ] パスワードは平文のまま保持されない。
- [ ] 追加したユーザでログインできる。
- [ ] ログインはユーザ名とパスワードで行い、メールアドレスではログインしない。

### REQ-004

ログイン中の、本機能が割り当てられた利用者がユーザを更新するとき、システムは当該ユーザのユーザ名、パスワード、またはメールアドレスを更新できること。

#### 受け入れ条件

- [ ] 未削除のユーザのユーザ名を変えられる。
- [ ] 未削除のユーザのパスワードを変えられる。
- [ ] 未削除のユーザのメールアドレスを変えられる。
- [ ] ユーザ名またはメールアドレスが空のときは更新できない。
- [ ] メールアドレスの形式が不正なときは更新できない。
- [ ] 変更後のユーザ名が既にあるときは失敗する。
- [ ] パスワードを変えたとき、新しいパスワードでログインできる。
- [ ] パスワードは平文のまま保持されない。
- [ ] 存在しないユーザ、または論理削除済みのユーザの更新は失敗する。

### REQ-005

ログイン中の、本機能が割り当てられた利用者がユーザを削除するとき、システムは当該ユーザを論理削除すること。ただし、操作している本人は削除できない。

#### 受け入れ条件

- [ ] 指定したユーザを論理削除できる。
- [ ] 削除したユーザはユーザ一覧の対象外になる。
- [ ] 削除したユーザはログインできない。
- [ ] 削除後もユーザのデータは残る。
- [ ] 存在しないユーザ、または既に論理削除済みのユーザの削除は失敗する。
- [ ] 自分自身の削除は失敗する。

### REQ-006

ログイン中の、本機能が割り当てられた利用者が機能一覧を要求したとき、システムは削除されていない機能を示すこと。

#### 受け入れ条件

- [ ] 識別子、タイトル、遷移先、アイコンが一覧に出る。
- [ ] 論理削除済みの機能は出ない。

### REQ-007

ログイン中の、本機能が割り当てられた利用者が機能を追加するとき、システムは識別子、タイトル、遷移先、アイコンで機能を追加すること。

#### 受け入れ条件

- [ ] 識別子、タイトル、遷移先、アイコンを指定して追加できる。
- [ ] 同じ識別子の機能を複数登録できない。
- [ ] アイコンはデータとして保持される。配信用の画像ファイルをディスク上に置かなくても追加できる。

### REQ-008

ログイン中の、本機能が割り当てられた利用者が機能を更新するとき、システムは当該機能のタイトル、遷移先、アイコンを更新できること。識別子は変えない。

#### 受け入れ条件

- [ ] 未削除の機能のタイトル、遷移先、アイコンを更新できる。
- [ ] 識別子は更新後も同じである。
- [ ] 存在しない機能、または論理削除済みの機能の更新は失敗する。

### REQ-009

ログイン中の、本機能が割り当てられた利用者が機能を削除するとき、システムは当該機能を論理削除すること。ただし、本機能自身は削除できない。

#### 受け入れ条件

- [ ] 指定した機能を論理削除できる。
- [ ] 削除した機能は機能一覧とメニューの対象外になる。
- [ ] 削除後も機能のデータは残る。
- [ ] 存在しない機能、または既に論理削除済みの機能の削除は失敗する。
- [ ] 本機能自身の削除は失敗する。

### REQ-010

ログイン中の、本機能が割り当てられた利用者が割当一覧を要求したとき、システムは削除されていないユーザへの、削除されていない機能の割当を示すこと。

#### 受け入れ条件

- [ ] ユーザ、機能、表示順が分かる。
- [ ] 論理削除済みのユーザまたは機能の割当は出ない。

### REQ-011

ログイン中の、本機能が割り当てられた利用者が割当を追加するとき、システムは未削除のユーザへ、未削除の機能を表示順付きで割り当てること。

#### 受け入れ条件

- [ ] 未削除のユーザへ、未削除の機能を表示順付きで割り当てられる。
- [ ] 既に割り当て済みの組み合わせを再度割り当てたときは失敗する。
- [ ] 存在しない、または論理削除済みのユーザや機能への割当は失敗する。

### REQ-012

ログイン中の、本機能が割り当てられた利用者が割当を外すとき、システムは当該割当を外すこと。ただし、操作している本人から本機能を外すことはできない。

#### 受け入れ条件

- [ ] 割り当て済みの機能を、そのユーザのメニューから外せる。
- [ ] 割り当てていない組み合わせを外そうとしたときは失敗する。
- [ ] 自分自身から本機能を外すことは失敗する。

### REQ-013

ユーザ・機能・割当の操作が試みられたとき、システムは当該試行の記録を log フォルダへ出力すること。

#### 受け入れ条件

- [ ] 追加・更新・削除・割当・割当解除の試行が log フォルダ配下のファイルに残る。
- [ ] 記録にはタイムスタンプが含まれる。
- [ ] 記録には区分（INF、WRN、ERR、DBG のいずれか）が含まれる。
- [ ] 記録には、入力のうち判断に使う値が含まれる。パスワードは含まれない。
- [ ] 記録には判断結果（成功または失敗）が含まれる。
- [ ] 失敗のとき、画面へ出さない内部理由が記録に含まれる。
- [ ] ファイルはサイズが大きくなったら新しいファイルへ切り替わる。

## 非機能要件

- 本機能の利用には認証を必須とする。利用可否は、ログイン中ユーザに本機能が割り当てられているかで判定する。他機能の API は使わない。
- ユーザ、機能、割当はシステム共通のデータとして保持する。本機能はそれを更新し、機能スキーマへ複製しない。スキーマは `public` とする。
- パスワードはハッシュ化して保存する。平文では保存しない。パスワードとセッション ID はログに出さない。
- 操作の記録は、入力された内容、それを元にした判断結果、正常系ではない場合の理由を契機として出力する。
- ログはファイルサイズでローテーションする。上限サイズと世代数は、機能の `.env` で指定する。コードに埋め込まない。
- 失敗時に画面へ出す文言は、内部の詳細な理由を含まない。内部理由はログにだけ残す。
- 本機能は `portal` の Python を import しない。ログイン画面は本機能では提供しない（`portal` でログインする）。

## 対象外

- ログイン画面、メニュー画面（`portal` が担う）
- 運用コマンド（`portal` が担う）
- 論理削除の取り消し
- パスワードのリセット、有効期限
- ロールや、機能の割当より細かい権限
- システム設定の変更
- 本機能の初期登録（機能マスタへの追加と、最初の運用者への割当は運用コマンドで行う）
