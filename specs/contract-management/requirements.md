# contract-management（契約管理） 要件定義

## 概要

利用者が、自分の契約（電気・動画配信・金融口座・ファンクラブなど）の情報と、解約するための手順を一元管理するための機能である。契約を伴わないアカウント（ユーザ名とパスワードだけを控えるもの）も同じ場所で管理する。ユーザ名とパスワードだけを手早く参照する画面も持つ。解約する契約の順序を決め、その順に「名称」と「解約方法」を PDF で出力できる。

最終的には `password-management` を本機能に統合して閉鎖する。そのため、当面は両機能が同じ情報を重複して持ち、`password-management` の既存データは本機能へ取り込む。

## 用語

| 用語 | 説明 |
|------|------|
| 契約 | 管理の 1 件分の記録。名称、区分、維持費、ログイン情報、解約方法などを持つ。 |
| 契約を伴う契約 | 契約状態（契約日、契約終了日、維持費、解約方法など）を管理する契約。 |
| 契約を伴わない契約 | 契約状態を持たず、ユーザ名とパスワードなどのログイン情報の管理だけが目的の契約。 |
| 区分 | 契約の分類。「その他」だけが最初から用意され、そのほかの区分（インフラ、動画配信、金融口座など）は、利用者が自分で作る。区分には、金融機関かどうかの指定を付けられる。 |
| 金融機関の区分 | 「金融機関」の指定を付けた区分。この区分の契約（銀行口座、クレジットカードなど）だけが、他の契約の支払方法に選べる。 |
| ステータス | 契約の状態。契約を伴うか伴わないかに関わらず、有効、休止中、解約のいずれか。 |
| 維持費 | 契約を維持するための費用。金額と、年間か月額かの別で表す。 |
| 依存契約 | その契約が成り立つ前提となる、他の契約。 |
| 契約日の精度 | 契約日をどこまで正確に分かっているか。年月日、年月、年、不明のいずれか。 |
| 削除 | 契約の記録を、削除フラグを立てて一覧などから除くこと。ステータスの解約とは別で、間違って作ったときなどに使う。 |
| 解約順 | 解約する契約の並び順。解約手順の PDF はこの順で出力する。 |
| アカウント一覧 | 契約かどうかに関わらず、ユーザ名とパスワードだけを手早く参照する画面。 |

## 要件一覧

### REQ-001: 契約の登録

ログイン中の利用者が契約を登録するとき、システムは名称を必須とし、次の項目を受け付けること。

- 契約を伴うか、伴わないか
- 区分（必須。既定は「その他」）
- ホームページ
- 維持費（金額、年間か月額か）、更新日
- ログイン方法（複数選択可）：ユーザ名とパスワード、パスキー、2段階認証（メール）、2段階認証（TEL）
- 2段階認証の送付先：2段階認証（メール）を選んだときはメールアドレス、2段階認証（TEL）を選んだときは電話番号
- ユーザ名、パスワード
- 登録メールアドレス
- 依存契約（複数選択可）
- 支払方法（他の契約を 1 つ選ぶ）
- メモ
- 解約方法
- 契約者名義、会員番号・契約番号
- 自動更新の有無
- 解約の受付期限（更新日の何日前までか）、解約手数料・違約金、最低契約期間
- 問い合わせ先（電話番号、メールアドレス、受付時間）
- 契約日、契約日の精度
- 無料期間の終了日
- 契約終了日
- ステータス

**受け入れ条件**

- 名称だけを入力して登録できる。名称が空文字・空白のみのときは登録できない。
- 契約を伴わない契約は、契約を伴う契約だけの項目（維持費、更新日、契約日、契約終了日、無料期間の終了日、解約方法、依存契約、支払方法、契約者名義、会員番号・契約番号、自動更新の有無、解約の受付期限、解約手数料・違約金、最低契約期間、問い合わせ先）を持たない。
- ステータスは、契約を伴うか伴わないかに関わらず必須とし、既定は有効とする。
- パスワードは、改行を含む複数行のテキストを入力できる。
- 維持費は、金額が 0 以上の整数のときだけ登録できる。金額を入れたときは、年間か月額かの別も必須とする。維持費を入れないこともできる。
- 契約日の精度が年月日のときは年月日、年月のときは年月、年のときは年を入力する。不明のときは入力しない。精度に合わない入力は登録できない。
- 契約終了日は、契約を伴う契約で、ステータスが解約のときだけ入力できる。
- 依存契約には、ログイン中利用者本人の、削除されていない他の契約だけを選べる。自分自身は選べない。
- 支払方法には、ログイン中利用者本人の、削除されていない他の契約のうち、金融機関の区分の契約だけを、1 つ選べる（契約を伴わない契約も選べる）。自分自身は選べない。選ばないこともできる。金融機関の区分以外の契約は、選べない。
- 契約者名義、会員番号・契約番号、解約手数料・違約金、問い合わせ先の電話番号・メールアドレス・受付時間は、文字列で入力する。入力は任意。
- 自動更新の有無は、あり、なし、未設定のいずれかとする。既定は未設定。
- 解約の受付期限は、更新日の何日前までかを、0 以上の整数（日数）で入力する。最低契約期間は、0 以上の整数（月数）で入力する。どちらも入力は任意。
- 無料期間の終了日は、年月日で入力する。入力は任意。
- 2段階認証（メール）を選んだときは、送付先のメールアドレスを入力できる。2段階認証（TEL）を選んだときは、送付先の電話番号を入力できる。選んでいない方式の送付先は入力できない。送付先は、未入力でも登録できる。
- 同じ名称の契約を登録できる。

### REQ-002: 契約の編集

ログイン中の利用者が登録済みの契約を編集するとき、システムは REQ-001 の項目を更新できること。

**受け入れ条件**

- REQ-001 の項目をすべて編集できる。入力の検査は登録時と同じ。
- 契約を伴うかどうかを、あとから切り替えられる。契約を伴わないに切り替えたとき、契約を伴う契約だけの項目は消えることを、操作の前に利用者へ示す。
- 存在しない、または削除済みの契約の編集は失敗する。
- 依存契約の関係が循環する（A が B に依存し、B が A に依存する、など）更新は失敗する。

### REQ-003: 契約の削除

ログイン中の利用者が契約を削除するとき、システムは削除フラグを立てること。ステータスの解約とは別の操作とすること。

**受け入れ条件**

- 契約を削除できる。削除した契約は、一覧・アカウント一覧・解約順・依存契約の選択肢に出ない。
- 削除しても記録は残り、削除フラグが立った状態になる。
- ステータスを解約にしても、契約は削除されず、一覧に残る。
- 他の契約から依存契約・支払方法として参照されている契約も削除できる。削除後、参照していた側の依存契約・支払方法の表示からは外れる。
- 存在しない、または既に削除済みの契約の削除は失敗する。

### REQ-004: 契約の一覧と絞り込み

システムは常に、ログイン中利用者本人の、削除されていない契約を一覧表示すること。利用者は、キーワード、区分、ステータス、契約の有無で絞り込めること。

**受け入れ条件**

- 一覧に、名称、区分、ステータス、維持費、更新日を表示する。
- キーワードは、名称・ホームページ・登録メールアドレス・ユーザ名・メモを対象に、大文字小文字を区別しない部分一致で絞り込む。パスワードは検索の対象にしない。
- 区分、ステータス、契約の有無（契約を伴う、伴わない）で絞り込める。条件を組み合わせたときは、すべてに合うものを表示する。
- 既定では、ステータスが解約の契約も含めて表示する。
- 該当が 0 件のときは、その旨が分かるように表示する。

### REQ-005: 契約の詳細表示

ログイン中の利用者が一覧から契約を選んだとき、システムは REQ-001 の項目をすべて表示すること。パスワードは既定でマスク表示とし、利用者の操作でマスクと平文表示を切り替えられること。

**受け入れ条件**

- 一覧の契約を選ぶと、その契約のすべての項目が表示される。
- パスワードは既定でマスク表示になり、表示切替の操作で平文表示に切り替えられる。
- 2段階認証の送付先（メールアドレス、電話番号）を表示する。
- ユーザ名、パスワード、登録メールアドレスを、それぞれクリップボードへコピーできる（パスワードはマスク表示中でもコピーできる）。
- ホームページが設定されているときは、そのページを開ける。
- 契約日は、精度に応じた形式（年月日、年月、年、または「不明」）で表示する。
- 依存契約と支払方法は、名称を表示する。それを選ぶと、その契約の詳細に移れる。
- この契約に依存している他の契約（依存されている契約）と、この契約を支払方法としている他の契約の名称も、一覧で確認できる。
- 契約者名義、会員番号・契約番号、自動更新の有無、解約の受付期限、解約手数料・違約金、最低契約期間、問い合わせ先、無料期間の終了日を表示する。問い合わせ先の電話番号、メールアドレス、会員番号・契約番号は、それぞれクリップボードへコピーできる。
- 詳細から、編集と削除の操作に進める。

### REQ-006: 区分の管理

ログイン中の利用者が区分を管理するとき、システムは区分の追加、名称の変更、削除を受け付けること。

**受け入れ条件**

- 「その他」の区分が、利用者ごとに最初から使える。そのほかの区分は、最初は無く、利用者が追加する。
- 「その他」は、名称の変更と削除ができない。金融機関の指定も付けられない。契約の区分の既定は「その他」とし、区分は必ずどれか 1 つを持つ。
- 区分の追加と変更で、金融機関かどうかを指定できる（既定は、金融機関ではない）。
- 金融機関の指定を外せるのは、その区分の契約を支払方法にしている契約が 1 件も無いときだけである。あるときは、外せない旨を表示する。
- 契約の区分を、金融機関の区分から、金融機関でない区分に変えられるのは、その契約が他の契約の支払方法になっていないときだけである。なっているときは、変更できない旨を表示する。
- 利用者は区分を追加できる。名称が空文字・空白のみのとき、または、同じ利用者の既存の区分と同じ名称のときは追加できない。
- 「その他」以外の区分の名称を変更できる。変更後の名称の検査は追加時と同じで、その区分を使っている契約の表示にも反映される。
- 「その他」以外の区分を削除できるのは、その区分を使っている、削除されていない契約が 1 件も無いときだけである。使われているときは、削除できない旨を表示する。
- 区分は、利用者本人のものだけを参照・操作できる。

### REQ-007: ユーザ名とパスワードのアカウント一覧

ログイン中の利用者がアカウント一覧を開いたとき、システムは契約かどうかに関わらず、削除されていない契約のうち、ユーザ名またはパスワードを持つものを、名称とユーザ名の一覧で表示すること。

**受け入れ条件**

- 契約を伴う契約と、契約を伴わない契約の両方を対象にする。ステータスが解約の契約も対象にする。
- 名称・ユーザ名・ホームページ・メモの、大文字小文字を区別しない部分一致で絞り込める。
- 一覧の各行で、ユーザ名とパスワードを、それぞれクリップボードへコピーできる。パスワードは一覧の表示ではマスクし、平文表示への切替も行える。
- 該当が 0 件のときは、その旨が分かるように表示する。

### REQ-008: 解約順の整理

ログイン中の利用者が解約順を整理するとき、システムは解約の対象とする契約の選択と、解約順の並べ替えを受け付けること。

**受け入れ条件**

- 解約の対象に選べるのは、契約を伴う契約のうち、ステータスが有効または休止中のものだけである。
- 契約を解約の対象に加える、解約の対象から外す、解約順を並べ替える、の操作ができる。
- 解約順は保存され、次に開いたときも同じ順で表示される。
- 解約の対象に加えた契約のステータスを解約にしたとき、削除したとき、契約を伴わないに切り替えたときは、その契約は解約の対象から外れる。
- 解約順の画面に、各契約の名称、解約方法、依存契約の名称を表示する。
- 解約順が、依存契約の関係と逆になっているとき（ある契約より先に、その契約が依存している契約を解約する並びになっているとき）は、その旨を警告として表示する。警告があっても、並びは保存できる。

### REQ-009: 解約手順の PDF 出力

ログイン中の利用者が解約手順の PDF 出力を行うとき、システムは解約順に、各契約の名称と解約方法を並べた PDF を出力すること。

**受け入れ条件**

- 解約の対象に加えた契約を、解約順に、名称と解約方法で並べた PDF をダウンロードできる。
- PDF には、パスワードを含めない。ユーザ名、登録メールアドレスも含めない。
- 解約方法が未入力の契約は、「未入力」と分かる表示にする。
- 解約の対象が 0 件のときは、PDF を出力できない旨を表示する。
- 日本語が文字化けしない。
- PDF には、出力した日付を含める。

### REQ-010: password-management からのデータの取り込み

システムは、`password-management` の削除されていないパスワードエントリを、本機能の契約を伴わない契約として取り込めること。

**受け入れ条件**

- 取り込みは、利用者ごとに、その利用者本人のエントリだけを対象にする。
- 取り込むとき、タイトルを名称、ユーザ名をユーザ名、パスワードをパスワード、サイトURL をホームページ、メモをメモに写す。区分は、その他にする。
- 取り込みは、何度実行しても、同じエントリが重複して作られない。
- 取り込み元（`password-management` のデータ）は、取り込みで変更しない。
- 取り込みの件数と、取り込めなかった件数・理由が確認できる。

### REQ-011: 操作の記録

システムは、契約・区分・解約順の登録・編集・削除・参照・PDF 出力・取り込みの試行について、入力された内容、それを元にした判断結果、正常系ではない場合の理由をログに残すこと。ただし、パスワードの値そのものはログに残さないこと。

**受け入れ条件**

- 契約の登録・編集・削除・一覧・アカウント一覧・詳細表示、区分の追加・変更・削除、解約順の変更、PDF 出力、取り込みの試行と成否がログに残る。
- 失敗のときは、内部理由がログに残る。
- パスワードの値、セッション ID はログに出ない。ユーザ名・登録メールアドレス・2段階認証の送付先の値は、ログに出さない。

### REQ-012: 利用者ごとのデータの分離

システムは常に、ログイン中利用者本人が登録した契約・区分・解約順だけを、参照・操作の対象とすること。

**受け入れ条件**

- 一覧・検索・詳細・編集・削除・アカウント一覧・解約順・PDF は、操作しているユーザ本人のデータだけを対象にする。
- 他ユーザの契約や区分の ID を直接指定しても、参照・操作できない。
- 依存契約・解約順に、他ユーザの契約を加えられない。

### REQ-013: 外部システム（生成AI など）からの参照・登録・更新

外部システム（生成AI など）が、API キーを使って、契約の現在の状態を参照し、契約を登録・更新するとき、システムは、パスワードの値を入出力の対象から除いて、これを許可すること。パスワードは、あとから人が画面で入力・変更する。

**受け入れ条件**

- API キーの持ち主本人の、削除されていない契約を、一覧と詳細で参照できる。一覧は、REQ-004 と同じ条件（キーワード、区分、ステータス、契約の有無）で絞り込める。
- 契約の項目は、パスワードの値を除く、REQ-001 のすべてを返す。依存契約・支払方法は、名称も分かる形で返す。パスワードについては、設定されているかどうかだけを返す。
- 区分の一覧と、解約順（解約の対象とその順序、解約方法）も、参照できる。
- どの応答にも、パスワードの値を含めない。パスワードの値を返す手段は、API キーでは用意しない。
- API キーで契約を登録できる。入力の検査は REQ-001 と同じ。パスワードの値は受け付けない（渡されたときは、失敗とし、保存しない）。登録した契約のパスワードは、未設定になる。
- API キーで契約を更新できる。入力の検査は REQ-002 と同じ。パスワードの値は受け付けず（渡されたときは、失敗とし、保存しない）、更新しても、保存済みのパスワードは変わらない（消えも、書き換わりもしない）。
- 契約の削除、区分の管理、解約順の変更、PDF 出力、取り込みは、API キーでは行えない。
- API キーの持ち主以外の契約は、参照も、更新もできない。登録される契約は、API キーの持ち主のものになる。
- 失効済み・有効期限切れの API キー、持ち主に本機能が割り当てられていない API キーでは、参照も、登録も、更新もできない。
- API キーによる参照・登録・更新の試行と結果が、REQ-011 と同様にログに残る。API キーのキー全体とそのハッシュは、ログに出ない。

### REQ-014: パスワードが未設定の契約の確認

ログイン中の利用者が契約を一覧・詳細で見るとき、システムは、ユーザ名とパスワードを使う契約のうち、パスワードが未設定のものを、見分けられるようにすること。

**受け入れ条件**

- 契約を伴う・伴わないに関わらず、ログイン方法にユーザ名とパスワードを選んでいて、パスワードが未設定の契約は、一覧と詳細で「パスワード未設定」と分かる。
- 一覧は、パスワードが未設定かどうかで、絞り込める。
- 人が詳細または編集で、パスワードを入力して保存すると、未設定の表示は消える。

## 認証の要否

本機能のすべての操作に認証を必要とする。利用できるのは、ログイン中で、本機能が割り当てられているユーザだけとする。論理削除済みのユーザまたは機能は利用できない。判定は他機能の API に依存しない。

他システム連携用の API キー認証は、REQ-013 の参照・登録・更新に限って使う。パスワードの値の入出力、削除、区分の管理、解約順の変更は、API キーでは行えない。

## 非機能要件

- パスワードは、`password-management` と同じく、DB に平文で保存する（暗号化保存は行わない）。ただし、ログには一切出さない。
- 一覧・アカウント一覧の応答にはパスワードを含めない扱いとし、表示・コピーのときに 1 件ずつ取得する（取得方法は設計で決める）。

## スコープ外

- パスワードの暗号化保存
- ログイン画面、メニュー画面（`portal` が担う）
- 本機能の初期登録（機能マスタへの追加と、利用者への割当はユーザ管理で行う）
- 他利用者との共有
- 変更履歴・バージョン管理
- 添付ファイル
- 更新日・契約終了日・無料期間の終了日・解約の受付期限の通知（メール等）
- 解約の実施記録、解約時の注意の項目
- 維持費の集計・グラフ
- 契約の実際の解約手続きの代行
- 外部システム向けの MCP サーバへのツールの追加（API を利用する別プロジェクト `mcp` で、本機能の API の承認後に別途行う）
- API キーによる契約の削除、区分の管理、解約順の変更
- `password-management` の閉鎖そのもの（統合後に別途判断する）
