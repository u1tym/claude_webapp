# 機能: password-management（パスワード管理）

## 目的

ログイン中の利用者が、自分専用のアカウント情報（ログインID・パスワードなど）を記録として登録・検索・閲覧・編集・削除できるようにする。他システムで使うアカウント情報を控えておくための、個人用の記録機能である。

## 背景

別サーバで稼働している既存のパスワード管理サービス（`sample/psinfo` 配下にソースコードを保管）と同等の機能を、本プロジェクトの機能の一つとして実装する。既存サービスのデータは、別途作成する移行スクリプトで本機能のデータベースへ取り込む。

## ユーザーストーリー

- 利用者として、他システムのアカウント情報を控えておきたい。なぜなら、忘れたときに参照したいから。
- 利用者として、多数のエントリからキーワードで絞り込みたい。なぜなら、件数が増えても目的のものをすぐ見つけたいから。
- 利用者として、一覧やうっかり画面を覗かれてもパスワードが見えないようにしたい。なぜなら、パスワードは機密情報だから。
- 利用者として、必要なときだけパスワードを表示したり、クリップボードにコピーしたりしたい。なぜなら、入力の手間を減らしたいから。
- 利用者として、登録したエントリを編集・削除したい。なぜなら、内容が変わったり不要になったりするから。
- 利用者として、自分が登録したエントリだけを扱いたい。なぜなら、他人のアカウント情報を見せたくないから。

## 用語

| 用語 | 意味 |
|------|------|
| パスワードエントリ | 1件のアカウント情報の記録。タイトル・ユーザ名・パスワード・サイトURL（任意）・メモ（任意）を持つ。 |
| タイトル | パスワードエントリの業務上の識別名。同一利用者の未削除のパスワードエントリの中で一意。 |
| ユーザ名 | 対象システムでのログインID等。 |
| パスワード | 対象システムのパスワード。改行を含む複数行のテキストも許容する（パスフレーズやワンタイムコード等の併記を想定）。 |
| マスク表示 | パスワードを `••••••••` のような記号に置き換えて、値が読めない状態で表示すること。 |

## 要件

要件は EARS の意味を保ち、日本語の文で書く。画面部品、テーブル定義、API パス、HTTP ステータスなど設計は書かない。

### REQ-001

本機能を利用するとき、システムはログインを必須とし、ログイン中ユーザに本機能が割り当てられているときだけ利用を許可すること。

#### 受け入れ条件

- [ ] 未ログインでは、パスワードエントリの参照も操作もできない。
- [ ] 本機能が割り当てられていないログイン中ユーザは、参照も操作もできない。
- [ ] 論理削除済みのユーザまたは本機能では、参照も操作もできない。
- [ ] 判定は他機能の API に依存しない。

### REQ-002

システムは常に、ログイン中ユーザ本人が登録したパスワードエントリだけを参照・操作の対象とすること。他の利用者が登録したパスワードエントリは、参照も操作もできないこと。

#### 受け入れ条件

- [ ] 一覧・検索・詳細取得・編集・削除は、操作しているユーザ本人が登録したパスワードエントリだけを対象にする。
- [ ] 他ユーザが登録したパスワードエントリの ID を直接指定しても、参照・操作できない。

### REQ-003

ログイン中の利用者がパスワードエントリを登録するとき、システムはタイトル・ユーザ名・パスワードを受け付け、サイトURL・メモは任意で受け付けること。

#### 受け入れ条件

- [ ] タイトル・ユーザ名・パスワードを入力して登録できる（サイトURL・メモは任意入力）。
- [ ] タイトル・ユーザ名は、空文字・空白のみは登録できない。
- [ ] パスワードは、空文字は登録できない（空白のみ、複数行は登録できる）。
- [ ] タイトルが、登録しようとしている利用者本人の未削除のパスワードエントリと重複するときは登録に失敗する。

### REQ-004

ログイン中の利用者が登録済みのパスワードエントリを編集するとき、システムはタイトル・ユーザ名・パスワード・サイトURL・メモを更新できること。

#### 受け入れ条件

- [ ] タイトル・ユーザ名・パスワード・サイトURL・メモを編集できる。
- [ ] タイトル・ユーザ名・パスワードの必須・空文字の扱いは登録時と同じ。
- [ ] 更新後のタイトルが、編集対象自身を除いた、同一利用者の未削除のパスワードエントリと重複するときは更新に失敗する。
- [ ] 存在しない、または既に論理削除済みのパスワードエントリの編集は失敗する。

### REQ-005

ログイン中の利用者が登録済みのパスワードエントリを削除するとき、システムは論理削除すること。削除後は一覧・検索・詳細取得の対象外とし、削除後に同じタイトルで新たに登録できること。

#### 受け入れ条件

- [ ] パスワードエントリを削除できる。削除後は一覧・検索・詳細取得に出ない。
- [ ] 削除しても記録は残り、削除フラグが立った状態になる。
- [ ] 削除済みのタイトルと同じタイトルで、新たにパスワードエントリを登録できる。
- [ ] 存在しない、または既に論理削除済みのパスワードエントリの削除は失敗する。

### REQ-006

システムは常に、ログイン中利用者本人が登録した、削除されていないパスワードエントリを一覧表示すること。利用者がキーワードを入力したとき、タイトル・ユーザ名・サイトURL・メモを対象に、大文字小文字を区別しない部分一致で絞り込むこと。

#### 受け入れ条件

- [ ] 削除されていないパスワードエントリを、タイトル・ユーザ名とともに一覧表示できる。
- [ ] キーワード検索は、タイトル・ユーザ名・サイトURL・メモのいずれかに部分一致すれば対象に含める。
- [ ] 検索は大文字小文字を区別しない。
- [ ] キーワードが空、または空白のみのときは、全件表示と同じ結果になる。
- [ ] 該当が0件のときは、その旨がわかるように表示する。

### REQ-007

ログイン中の利用者が一覧からパスワードエントリを選んだとき、システムはタイトル・ユーザ名・パスワード・サイトURL・メモを表示すること。パスワードは既定でマスク表示とし、利用者の操作でマスクと平文表示を切り替えられること。ユーザ名とパスワードは、それぞれクリップボードへコピーできること。

#### 受け入れ条件

- [ ] 一覧の行を選ぶと、そのパスワードエントリの詳細が表示される。
- [ ] パスワードは既定でマスク表示になる。
- [ ] 表示切替の操作で、マスク表示と平文表示を切り替えられる。
- [ ] ユーザ名をクリップボードへコピーできる。
- [ ] パスワードをクリップボードへコピーできる（マスク表示中でもコピーできる）。
- [ ] サイトURLが設定されているときは、そのURLを開ける。
- [ ] 詳細表示から、編集・削除の操作に進める。

### REQ-008

システムは、パスワードエントリの登録・編集・削除・参照の試行について、入力された内容、それを元にした判断結果、正常系ではない場合の理由をログに残すこと。ただし、パスワードの値そのものはログに残さないこと。

#### 受け入れ条件

- [ ] 登録・編集・削除・一覧取得・検索の試行と成否がログに残る。
- [ ] 失敗のときは内部理由がログに残る。
- [ ] パスワード（psword）の値、セッション ID はログに出ない。

## 非機能要件

- 本機能の利用には認証を必須とする。利用可否は、ログイン中ユーザに本機能が割り当てられているかで判定する。他機能の API は使わない。
- パスワードエントリは、ログイン中ユーザ本人が登録したものだけを扱う。他ユーザのデータは参照させない。
- 本機能は `portal` の Python を import しない。ログイン画面は本機能では提供しない（`portal` でログインする）。
- パスワードは平文で保存する（既存の別サーバ版と同じ方式を踏襲する。暗号化保存は対象外）。ただし、ログには一切出さない。
- 操作の記録は、入力された内容、それを元にした判断結果、正常系ではない場合の理由を契機として出力する。
- ログはファイルサイズでローテーションする。上限サイズと世代数は、機能の `.env` で指定する。コードに埋め込まない。
- 失敗時に画面へ出す文言は、内部の詳細な理由を含まない。内部理由はログにだけ残す。

## 対象外

- ログイン画面、メニュー画面（`portal` が担う）
- パスワードの暗号化保存、強度チェック、有効期限管理
- 他利用者とのパスワードエントリの共有
- 変更履歴・バージョン管理
- 添付ファイル
- 本機能の初期登録（機能マスタへの追加と、利用者への割当はユーザ管理で行う）
- 別サーバ版からのデータ移行そのもの（移行スクリプトは本要件定義の対象外とし、別途作成する）
