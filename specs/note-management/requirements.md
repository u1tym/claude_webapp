# note-management（ノート管理）要件定義

## 概要

ログイン中の利用者が、自分専用のノートを、フォルダとファイルの階層で整理し、ファイルの中に、文章・URL・行動予定・チェックリスト・画像・添付ファイルなどの断片（パーツ）を並べて記録・閲覧・編集できる機能である。ファイルは、PDF として出力（印刷）できる。

別サーバで稼働している既存のノート管理サービス（`sample/note` 配下にソースコードを保管）と同等の機能を、本プロジェクトの機能の一つとして実装する。ただし、サンプルにある「表」のパーツ（セルの数式計算を含む）は、本機能では提供しない。あわせて、既存サービスのデータを、本機能のデータベースへ移行するプログラムを提供する。移行は、ファイルへのエクスポート・インポートではなく、移行元と移行先の両方のデータベースへ同時に接続して行う。

サンプルは、削除したフォルダ・ファイル・パーツを元に戻す（削除解除）操作を、サーバの機能として持つが、画面には出していない。本機能は、削除済みの表示と削除解除を、画面から行えるようにする。

## 用語

| 用語 | 説明 |
|------|------|
| フォルダ | ファイルをまとめる入れ物。名前と並び順を持つ。フォルダの中に、さらにフォルダを作れる（階層）。最上位のフォルダを、ルートフォルダと呼ぶ。 |
| ファイル | 1 つのノート。タイトルと並び順を持ち、必ず、いずれかのフォルダの中に置く（ルートの直下には置けない）。パーツを持つ。 |
| パーツ | ファイルを構成する断片。種別を持ち、ファイルの中で並び順を持つ。 |
| パーツの種別 | テキスト、Markdown、TeX、URL、行動予定、チェックリスト、JPEG（画像）、PNG（画像）、バイナリ（添付ファイル）。 |
| 論理削除・削除済み | フォルダ・ファイル・パーツを、データは残したまま、通常の表示から外すこと。削除解除で元に戻せる。 |
| 祖先が削除済み | あるフォルダまたはファイルの上位のフォルダのいずれかが削除済みであること。この状態の子は、自身が削除されていなくても、削除済みとして扱う。 |
| 過去世代 | 画像・バイナリのパーツの内容を差し替えたときに、差し替え前の内容を保管したもの。 |
| 行動予定 | 地点（場所・時刻）と、地点間の経由メモを、順に並べた記録。 |
| チェックリスト | タイトル、カテゴリ、チェック項目（タイトルとチェック状態）を持つ一覧。 |
| PDF 出力 | 1 つまたは複数のファイルの内容を、印刷用のレイアウトで表示し、ブラウザの印刷機能から PDF などとして出力すること。 |
| 移行元 | 既存のノート管理サービスの DB。 |
| 移行先 | 本機能の DB。 |

## 要件一覧

### REQ-001: 利用可否の判定

本機能を利用するとき、システムはログインを必須とし、ログイン中ユーザに本機能が割り当てられているときだけ利用を許可すること。

**受け入れ条件**

- 未ログインでは、フォルダ・ファイル・パーツの参照も操作もできない。
- 本機能が割り当てられていないログイン中ユーザは、参照も操作もできない。
- 論理削除済みのユーザまたは本機能では、参照も操作もできない。
- 判定は他機能の API に依存しない。

### REQ-002: 本人のデータだけを扱う

システムは常に、ログイン中ユーザ本人が登録したフォルダ・ファイル・パーツ（およびその過去世代、チェックリスト）だけを、参照・操作の対象とすること。他の利用者が登録したものは、参照も操作もできないこと。

**受け入れ条件**

- 一覧・取得・登録・変更・削除・削除解除・並び替え・移動は、操作しているユーザ本人のデータだけを対象にする。
- 他ユーザのフォルダ・ファイル・パーツ・過去世代・チェックリストの識別子を直接指定しても、参照・操作できない（存在しないものとして扱う）。
- 他ユーザのフォルダを、移動先や親として指定しても、指定できない。

### REQ-003: フォルダ・ファイルの一覧（ツリー）

ログイン中の利用者がノートを開いたとき、システムは本人のルートフォルダを表示し、フォルダを展開すると、その中のフォルダとファイルを表示すること。

**受け入れ条件**

- 初期表示は、ルートフォルダの一覧である。フォルダを展開すると、その直下のフォルダとファイルが出る。
- フォルダとファイルは、それぞれ、並び順（登録時に末尾に付く。並び替えで変わる）の昇順に表示する。
- 削除済みのフォルダ・ファイルと、祖先が削除済みのフォルダ・ファイルは、通常の表示には出さない。
- ファイルを選ぶと、そのファイルの内容の画面（REQ-007）へ進める。
- 何もないときは、その旨を表示する。

### REQ-004: フォルダの管理

ログイン中の利用者がフォルダを操作するとき、システムはフォルダの作成・名前変更・移動・並び替え・削除を、本人のフォルダに対して行えること。

**受け入れ条件**

- ルートフォルダと、フォルダの中のフォルダ（子フォルダ）を作成できる。名前は必須（空白のみは不可）。並び順は、同じ親の中の末尾になる。
- 名前を変更できる。同じ親の中に、削除されていない同名のフォルダがあるときは、作成・名前変更・移動のいずれも、受け付けず、理由を表示する。
- フォルダを、別のフォルダの中、またはルートへ移動できる。移動したフォルダは、移動先の末尾に並ぶ。自分自身や、自分の子孫のフォルダの中へは移動できない（受け付けず、理由を表示する）。
- 同じ親の中の、隣り合う 2 つのフォルダの並び順を入れ替えられる。
- フォルダを削除できる（論理削除）。フォルダを削除しても、その中のフォルダ・ファイルのデータは変更しない。それらは、祖先が削除済みとして、表示から外れる。
- 削除済みのフォルダに対して、名前変更・移動・並び替えはできない。

### REQ-005: ファイルの管理

ログイン中の利用者がファイルを操作するとき、システムはファイルの作成・タイトル変更・移動・並び替え・削除を、本人のファイルに対して行えること。

**受け入れ条件**

- フォルダの中に、ファイルを作成できる。ルートの直下（フォルダの外）には作成できない。タイトルは必須（空白のみは不可）。並び順は、同じフォルダの中の末尾になる。
- タイトルを変更できる。同じフォルダの中に、削除されていない同じタイトルのファイルがあるときは、作成・タイトル変更・移動のいずれも、受け付けず、理由を表示する。
- ファイルを、別のフォルダの中へ移動できる。移動したファイルは、移動先の末尾に並ぶ。
- 同じフォルダの中の、隣り合う 2 つのファイルの並び順を入れ替えられる。
- ファイルを削除できる（論理削除）。ファイルを削除しても、そのパーツのデータは変更しない。
- 削除済みのファイルに対して、タイトル変更・移動・並び替えはできない。

### REQ-006: 削除済みの表示と削除解除

ログイン中の利用者が削除済みの項目を表示したとき、システムは削除済みのフォルダ・ファイル・パーツを、削除済みと分かる形で表示し、削除解除できること。

**受け入れ条件**

- フォルダ・ファイルの一覧で、削除済みを含めて表示する切り替えができる。削除済みのもの（祖先が削除済みのものを含む）は、削除済みと分かる形で表示する。
- ファイルの内容の画面で、削除済みのパーツを含めて表示する切り替えができる。削除済みのパーツは、削除済みと分かる形で表示する。
- 削除済みのフォルダ・ファイル・パーツを、削除解除できる。祖先が削除済みで表示されているだけのものは、その祖先を削除解除すると、元に戻る。
- フォルダ・ファイルの削除解除のとき、同じ親の中に、削除されていない同名（ファイルは同タイトル）のものがあるときは、受け付けず、理由を表示する。
- 削除解除したフォルダ・ファイル・パーツの並び順が、同じ親（ファイルの中）の他の項目と重なるときは、末尾に付け直す。
- 削除済みのフォルダの中にあるファイル・フォルダを開いて内容を見ることはできる。削除済みのファイルの内容（パーツ）も表示できる。

### REQ-007: ファイルの内容の表示

ログイン中の利用者がファイルを開いたとき、システムはファイルのタイトル・所属するフォルダ名と、そのパーツを、並び順に、種別に応じた形で表示すること。

**受け入れ条件**

- パーツは、並び順の昇順に表示する。削除済みのパーツは、通常は表示しない。
- テキストは、そのまま（改行を保って）表示する。
- Markdown は、整形して表示する。TeX は、数式を組版して表示する。
- URL は、開けるリンクとして表示する。
- 行動予定は、地点・時刻・経由メモを、順に並べて表示する。
- チェックリストは、タイトル（空なら非表示）、カテゴリごとの項目とチェック状態を表示する。
- 画像（JPEG・PNG）は、画像を、指定された倍率で表示し、タイトル（空なら非表示）とマーカーを重ねて表示する。
- バイナリは、ファイル名とサイズを表示し、ダウンロードできる。
- パーツが 1 件もないときは、その旨を表示する。
- 存在しない、または他ユーザのファイルを開こうとしたときは、「見つかりません」と表示する。

### REQ-008: パーツの管理

ログイン中の利用者がファイルの中のパーツを操作するとき、システムは、パーツの追加・編集・削除・並び替えを行えること。

**受け入れ条件**

- 種別（テキスト、Markdown、TeX、URL、行動予定、チェックリスト、JPEG、PNG、バイナリ）を選んで、ファイルの末尾にパーツを追加できる。
- 追加した内容を、あとから編集できる。テキスト・Markdown・TeX・URL は、本文（URL の文字列）を編集できる。
- パーツの種別を、テキスト・Markdown・TeX・URL・行動予定・画像・バイナリの間で変更できる。チェックリストへの変更、チェックリストからの変更はできない（受け付けず、理由を表示する）。
- パーツを削除できる（論理削除）。
- 同じファイルの中の、隣り合う 2 つのパーツの並び順を入れ替えられる。
- 本文が空のテキスト・Markdown・TeX・URL のパーツも、登録できる。
- 画像・バイナリのファイルの大きさは、1 件あたり 10 MB までとする。超えるときは、受け付けず、理由を表示する。
- 削除済みのファイルのパーツを、追加・編集・並び替えはできない。

### REQ-009: 画像パーツ

ログイン中の利用者が画像（JPEG・PNG）のパーツを扱うとき、システムは、ファイル名・タイトル・表示倍率・マーカーを、画像とともに保存し、表示・編集できること。

**受け入れ条件**

- 画像は、選んだファイルから登録する。ファイル名は必須である。タイトルは任意である。
- 表示倍率は、25%〜400%の範囲で指定できる（既定は 100%）。範囲の外は受け付けない。
- 画像の上に、マーカーを置ける。マーカーには、家マーカーと、番号マーカーがある。マーカーは、画像上の位置と、文字を持つ。番号マーカーは、1 以上の番号を持つ。1 つの画像のマーカーは、100 個までとする。
- マーカーは、編集画面で、追加・移動・文字の変更・削除ができる。
- 画像を差し替えたときは、マーカーを空にする。タイトルや倍率、マーカーだけを変えるときは、画像は変わらない。
- 不正なマーカー（位置が範囲外、番号のないもの、番号を持つ家マーカー、重複した識別子）は、受け付けず、理由を表示する。

### REQ-010: 画像・バイナリの過去世代

ログイン中の利用者が、画像・バイナリのパーツの内容（画像またはファイルの中身、種別、ファイル名）を差し替えたとき、システムは、差し替え前の内容を過去世代として保管し、あとからダウンロードできること。

**受け入れ条件**

- 差し替えのたびに、差し替え前の内容が、世代番号（そのパーツの中で 1 から増える）付きで保管される。
- タイトル・倍率・マーカーだけを変えたときは、世代は増えない。
- 保管する世代の数には上限がある（既定は 3 件）。超えた分は、古い世代から削除する。
- ファイルの内容の画面で、そのパーツの過去世代の一覧（世代番号・ファイル名・種別・保管の日時）を見て、選んだ世代の内容をダウンロードできる。
- 過去世代は、本人のものだけが対象である。

### REQ-011: 行動予定パーツ

ログイン中の利用者が行動予定のパーツを扱うとき、システムは、地点（場所・時刻）と、地点間の経由メモを、順に並べて保存し、表示・編集できること。

**受け入れ条件**

- 地点は、場所と時刻を持つ。2 番目以降の地点は、時刻を 1 つ持つか、到着時刻と出発時刻を持つかのどちらかにできる（両方は指定できない）。時刻は、自由に書ける。
- 経由メモは、隣り合う 2 つの地点の間に、メモ（1 行）と補足（複数行）を持てる。経由メモの数は、地点の数 − 1 である。
- 地点・経由メモの、どれか 1 件以上に内容がないと、保存できない（受け付けず、理由を表示する）。末尾の、すべて空の地点は、保存のときに取り除く。
- 場所・メモ・補足の、途中や先頭の空白は保ち、末尾の空白だけを取り除いて保存する。
- 保存した内容は、地点と経由メモを順に並べて表示する。

### REQ-012: チェックリストパーツ

ログイン中の利用者がチェックリストのパーツを扱うとき、システムは、タイトル・カテゴリ・チェック項目を保存し、表示・編集できること。

**受け入れ条件**

- チェックリストのパーツを追加すると、タイトルが空で、カテゴリも項目もないチェックリストができる。
- タイトルを変更できる。タイトルが空のときは、表示しない。
- カテゴリを追加・名前変更・削除・並び替えできる。カテゴリの名前は、自由に書けるが、同じチェックリストの中で同じ名前は付けられない（削除されていないカテゴリの間で）。名前が空のカテゴリ（無名カテゴリ）は、1 つだけ持て、見出しなしで項目だけを表示する。
- チェック項目を、カテゴリの中に、追加・タイトル変更・チェックのオンオフ・削除・並び替え・別のカテゴリへの移動ができる。カテゴリを指定しない追加は、無名カテゴリへ入り、無名カテゴリがなければ、自動で作る。
- カテゴリと項目の並び替え・移動は、ドラッグ操作で行える（ドラッグ操作を使えなくても、ほかの方法で並び替えできる）。
- カテゴリ・項目の削除は、論理削除である。カテゴリを削除すると、その中の項目も削除される。削除したカテゴリ・項目を元に戻す操作は提供しない。
- チェックのオンオフは、編集の状態のときだけ行える。

### REQ-013: PDF 出力

ログイン中の利用者が PDF 出力を指定したとき、システムは、指定したファイルの内容を、印刷用のレイアウトで表示し、ブラウザの印刷機能から出力できること。

**受け入れ条件**

- ファイルの内容の画面から、そのファイル 1 件を出力できる。
- フォルダ・ファイルの一覧から、複数のファイルを選び、選んだ順に連結して出力できる。選んだファイルの順を、出力の前に入れ替えられ、選択から外せる。
- 複数のファイルの出力では、ファイルごとに改ページするかを選べる（既定は改ページする）。
- 出力には、フォルダ名とファイルのタイトル、削除されていないパーツを、種別に応じた形で含める。
- 画像・行動予定・チェックリスト・Markdown・TeX・URL・テキストが、画面と同じ内容で出力される。バイナリは、ファイル名とサイズの表示とする。

### REQ-014: 操作の記録（ログ）

システムは、本機能の主な操作の試行について、入力された内容、それを元にした判断結果、正常系ではない場合の理由をログに残すこと。

**受け入れ条件**

- フォルダ・ファイル・パーツ・チェックリストの、作成・変更・移動・削除・削除解除・並び替え、一覧取得、ファイル取得の試行と成否がログに残る。
- 失敗のときは内部理由がログに残る。
- セッション ID、パスワード、Cookie の値はログに出ない。
- パーツの本文・画像・ファイルの中身そのものは、ログに出さない（識別子・種別・大きさだけ）。
- 失敗時に画面へ出す文言は、内部の詳細な理由を含まない。内部理由はログにだけ残す。

### REQ-015: 移行元・移行先への同時接続

移行プログラムを実行するとき、システムは、移行元と移行先の両方のデータベースへ同時に接続し、移行元から読み取ったデータを、直接、移行先へ書き込むこと。

**受け入れ条件**

- エクスポート用のファイルや、中間ファイルを作らずに移行できる。
- 移行元の接続情報（ホスト、ポート、データベース名、ユーザ、パスワード）は、実行時の引数または環境変数で指定できる。移行先の接続情報は、本機能の設定（`backend/.env`）を用いる。
- 移行元へは読み取りだけを行い、移行元のデータを変更・削除しない。
- 接続に失敗したときは、どちらのデータベースに失敗したかがわかるメッセージを表示して終了する。移行元・移行先のパスワードは、画面にもログにも出さない。

### REQ-016: 移行の対象と対応付け

移行プログラムは、移行元のノート管理サービスのデータを、指定した利用者のデータとして、移行先へ移行すること。

**受け入れ条件**

- 移行元の利用者（アカウント）を、ユーザ名で指定し、移行先に、同じユーザ名の利用者がいるとき、その利用者のデータとして移行する。移行元・移行先のどちらかに、その利用者がいない（移行先は論理削除済みを含む）ときは、何も移行せずに終了する。
- 移行の対象は、フォルダ、ファイル、パーツ、画像・バイナリの過去世代、チェックリスト（タイトル・カテゴリ・項目）である。
- 表のパーツ（およびその表・セル・列幅）は、移行しない。対象外として、一覧表示する。
- 削除済みのフォルダ・ファイル・パーツは、削除済みの状態のまま、移行する。
- チェックリストの、削除済みのカテゴリ・項目は、元に戻す操作がないため、移行しない。対象外として、件数を表示する。
- フォルダの階層、名前、ファイルのタイトル、並び順、パーツの種別・本文・ファイル名・タイトル・マーカー・倍率、過去世代の世代番号・内容・保管の日時は、移行元の値をそのまま用いる。
- 識別子は、移行先で新しく採番する。パーツが指すチェックリストの参照は、新しい識別子に付け替える。
- 移行元の状態が、本機能の規則に合わないとき（種別の値が想定外など）、そのデータは移行せず、失敗として一覧表示する。

### REQ-017: 移行の再実行と整合性

移行プログラムは、途中で中断しても、再度実行すれば続きから移行でき、ファイル 1 件ごとに、全データが揃ったときだけ移行先へ確定すること。

**受け入れ条件**

- フォルダの階層を先に移行し、ファイルは 1 件ごとに、ファイル本体・全パーツ・過去世代・チェックリストを、まとめて確定する。途中で失敗したファイルは、そのファイルのデータを移行先に残さない。
- 移行済みのフォルダ・ファイルは、再実行時にスキップする。移行済みかどうかは、指定した利用者の、移行先の同じ親（フォルダ）の中に、同じ名前（ファイルは同タイトル）で、同じ削除状態のものがあるかで判定する。スキップしたものは一覧表示する。
- 移行したファイルは、移行先で、パーツ・過去世代の数が、移行元（表のパーツを除く）と一致することを確認する。一致しないときは、そのファイルを移行先に残さず、失敗として一覧表示する。
- ファイル 1 件の失敗は、ほかのファイルの移行を止めない。最後に失敗したものを一覧表示し、失敗があったときは、終了状態でそれがわかる。
- 画像・バイナリの本文は、移行前後で一致することを確認する。

### REQ-018: 移行の実行と結果の報告

移行プログラムは、実際に書き込む前に内容を確認でき、実行後に結果を報告すること。

**受け入れ条件**

- 実際には書き込まずに、移行の対象と件数、対象外の一覧を表示して終了する確認用の実行（ドライラン）ができる。
- 実行中は、ファイル 1 件ごとに、進捗（何件中何件目、フォルダの経路とタイトル）を表示する。
- 実行後に、種別（フォルダ・ファイル・パーツ・過去世代・チェックリスト）ごとに、移行した件数、スキップした件数、対象外の件数、失敗の件数と、それぞれの内訳を表示する。
- 移行手順（事前準備、実行方法、再実行、後片付け）を、README として、移行プログラムとともに提供する。

## 認証の要否

本機能の画面と操作は、すべて認証を必須とする。利用可否は、ログイン中ユーザに本機能が割り当てられているかで判定する（REQ-001）。ログイン画面とメニュー画面は本機能では提供しない（`portal` が担う）。

移行プログラムは、コマンドラインから、管理者が両方のデータベースの接続情報と利用者名を指定して実行するもので、画面のログインは介さない。

## スコープ外

- ログイン画面、メニュー画面（`portal` が担う）
- 本機能の初期登録（機能マスタへの追加と、利用者への割当はユーザ管理で行う）
- 表のパーツ（セルの入力・数式計算・行列の追加削除・列幅・表のタイトル）と、そのデータの移行
- チェックリストの削除済みのカテゴリ・項目の削除解除（サンプルにない）
- ファイル・フォルダの検索、他の利用者との共有（サンプルに無い機能）

- 移行元・移行先以外のデータベースや、ファイルを経由した移行（エクスポート・インポート方式）
- 移行後の移行元データの削除
