# room（ROOM）要件定義

## 概要

自室の照明・スピーカー・玄関ドアの状態を、画面で一目で確認し、そのまま切り替えるための機能である。機器の実体は SwitchBot 製品であり、利用者は SwitchBot のアプリを開かずに操作できる。あわせて、毎日・曜日・祝日と時刻を指定して、決まった切替を自動で行える。AI（MCP クライアント）からも同じ操作を行えるよう、操作は API として提供する。利用者は 1 人を想定する。

## 用語

| 用語 | 説明 |
|------|------|
| ROOM | 本機能。自室の機器の状態表示と操作を行う。 |
| 機器 | ROOM が扱う操作対象。電灯、間接照明、屋内スピーカー、枕元スピーカー、玄関ドアの 5 つ。 |
| 電灯 | 室内の電灯。状態は ON / OFF。現時点では未実装で、常に OFF と表示する。 |
| 間接照明 | 間接照明。状態は ON / OFF。 |
| 屋内スピーカー | 屋内のスピーカー。状態は ON / OFF。 |
| 枕元スピーカー | 枕元のスピーカー。状態は ON / OFF。 |
| 玄関ドア | 玄関のドア錠。状態は施錠中 / 開錠中。電池残量を併せて持つ。 |
| 電池残量 | 玄関ドアの錠の電池の残量。表示のみで、変更できない。 |
| 状態 | 各機器が今取っている値。 |
| 取得日時 | 機器の状態を取得した日時。 |
| 個別切替 | 1 つの機器だけの状態を変えること。 |
| 一括切替 | 複数の機器の状態を、決まった組み合わせで一度に変えること。屋内スピーカー選択、枕元スピーカー選択、電灯選択、間接照明選択、お出かけの 5 種がある。 |
| 屋内スピーカー選択 | 屋内スピーカーを ON、枕元スピーカーを OFF にする一括切替。 |
| 枕元スピーカー選択 | 屋内スピーカーを OFF、枕元スピーカーを ON にする一括切替。 |
| 電灯選択 | 電灯を ON、間接照明を OFF にする一括切替。 |
| 間接照明選択 | 電灯を OFF、間接照明を ON にする一括切替。 |
| お出かけ | 電灯、間接照明、屋内スピーカー、枕元スピーカーをすべて OFF にする一括切替。玄関ドアは変えない。 |
| 定期実行 | 指定した日と時刻に、一括切替を自動で行うこと。 |
| 実行条件 | 定期実行を行う日の指定。毎日、曜日の指定、祝日の指定のいずれか。 |
| 祝日 | 日本の国民の祝日（振替休日を含む）。 |
| ログ | 処理の入力、判断結果、正常系ではない場合の理由を、タイムスタンプと区分付きで残す記録。 |

## 要件一覧

### REQ-001: 機器の状態の表示

利用者が ROOM の画面を開いたとき、システムは各機器の状態と取得日時を表示すること。電灯、間接照明、屋内スピーカー、枕元スピーカーは ON / OFF を、玄関ドアは施錠中 / 開錠中と電池残量を示すこと。

**受け入れ条件**

- 画面を開くと、5 つの機器の状態が表示される。
- 取得日時（年月日と時分秒）が表示される。
- 電灯、間接照明、屋内スピーカー、枕元スピーカーは ON か OFF かが分かる。
- 玄関ドアは施錠中か開錠中かが分かり、電池残量が表示される。
- 状態の取得に失敗した機器は、取得できなかったことが分かり、他の機器の表示は妨げられない。

### REQ-002: 状態の図示

システムは、各機器の状態を、文字だけでなく図で示すこと。ON / OFF と施錠中 / 開錠中は、色だけで区別せず、見た目や文言でも区別できること。

**受け入れ条件**

- 各機器が、部屋を表す 1 つの図の中のパーツとして示される。
- 各パーツは、現在の状態によって見た目が変わる。
- 状態は、色以外の手がかり（形、記号、文言のいずれか）でも区別できる。
- PC の画面でもスマートフォンの画面でも、すべてのパーツを識別できる。

### REQ-003: 状態の再取得

利用者が更新を指示したとき、システムは各機器の状態を取得し直し、表示と取得日時を更新すること。

**受け入れ条件**

- 更新を指示すると、表示中の状態と取得日時が新しくなる。
- 取得中であることが分かり、取得中は重ねて更新できない。
- 機器の状態を変えたあとは、変えた結果が表示に反映される。

### REQ-004: 機器の個別切替

利用者が、間接照明、屋内スピーカー、枕元スピーカーのパーツを操作したとき、システムはその機器の状態を ON と OFF の間で切り替えること。

**受け入れ条件**

- 間接照明のパーツを操作すると、現在 OFF なら ON に、現在 ON なら OFF になる。
- 屋内スピーカーと枕元スピーカーのパーツでも、同様に切り替わる。
- 切り替えに成功したとき、パーツの見た目が新しい状態になる。
- 切り替えに失敗したとき、失敗したことが利用者に分かり、表示は元の状態のままである。
- 1 つの機器の切り替えは、他の機器の状態を変えない。

### REQ-005: 玄関ドアの個別切替

利用者が玄関ドアのパーツを操作したとき、システムは確認を求めたうえで、施錠中と開錠中の間で切り替えること。確認で取り消したときは、状態を変えないこと。

**受け入れ条件**

- 玄関ドアのパーツを操作すると、切り替える内容（施錠するか、開錠するか）を示す確認が表示される。
- 確認で承認したときだけ、玄関ドアの状態が切り替わる。
- 確認で取り消したときは、玄関ドアの状態は変わらない。
- 切り替えに失敗したとき、失敗したことが利用者に分かり、表示は元の状態のままである。
- 電池残量のパーツは、操作しても何も起きない。

### REQ-006: 電灯の扱い（未実装）

システムは、電灯を常に OFF として表示すること。利用者が電灯のパーツを操作しても、システムは何も行わないこと。電灯の実際の制御は、本要件の範囲外であり、後日の改訂で扱う。

**受け入れ条件**

- 電灯は、常に OFF と表示される。
- 電灯のパーツを操作しても、状態は変わらず、機器への指示も行われない。
- 電灯が未実装であることが、画面上で利用者に分かる。

### REQ-007: 一括切替

利用者が一括切替を指示したとき、システムは、その一括切替が定める組み合わせの状態に、各機器を変えること。一括切替は、屋内スピーカー選択、枕元スピーカー選択、電灯選択、間接照明選択、お出かけの 5 種とする。

**受け入れ条件**

- 屋内スピーカー選択で、屋内スピーカーが ON、枕元スピーカーが OFF になる。
- 枕元スピーカー選択で、屋内スピーカーが OFF、枕元スピーカーが ON になる。
- 電灯選択で、電灯が ON、間接照明が OFF になる。ただし電灯が未実装の間は、電灯は OFF のまま表示され、間接照明だけが OFF になる。
- 間接照明選択で、電灯が OFF、間接照明が ON になる。
- お出かけで、電灯、間接照明、屋内スピーカー、枕元スピーカーがすべて OFF になる。
- 一括切替は、玄関ドアの状態を変えない。
- 一括切替の一部の機器で失敗したとき、どの機器が成功し、どの機器が失敗したかが分かる。成功した機器の状態は元に戻さない。
- 一括切替のあと、表示は各機器の最新の状態になる。

### REQ-008: 定期実行の登録・変更・削除

利用者が、定期実行の登録、変更、削除を行えること。定期実行は、実行条件、時刻、実行する一括切替を持つこと。

**受け入れ条件**

- 実行条件として、毎日、曜日の指定、祝日の指定のいずれかを選べる。
- 曜日の指定では、月曜から日曜のうち 1 つ以上の曜日を選べる。
- 祝日の指定では、祝日に当たる日だけを対象にできる。
- 時刻を、時と分（日本標準時）で指定できる。
- 実行する一括切替を、屋内スピーカー選択、枕元スピーカー選択、電灯選択、間接照明選択、お出かけから選べる。玄関ドアの施錠・開錠は選べない。
- 定期実行を、一覧で確認できる。
- 定期実行ごとに、有効と無効を切り替えられる。
- 登録した定期実行を、変更、削除できる。
- 必須項目が足りないとき、または時刻の形式が正しくないとき、登録も変更もできず、理由が分かる。

### REQ-009: 定期実行の自動実行

指定された日と時刻になったとき、システムは、有効な定期実行について、指定された一括切替を実行すること。無効な定期実行は実行しないこと。同じ定期実行を、同じ日の同じ時刻に重ねて実行しないこと。

**受け入れ条件**

- 実行条件が毎日のとき、毎日、指定した時刻に実行される。
- 実行条件が曜日の指定のとき、指定した曜日の、指定した時刻に実行される。
- 実行条件が祝日の指定のとき、祝日に当たる日の、指定した時刻に実行される。祝日以外の日には実行されない。
- 無効な定期実行は、実行されない。
- 時刻の判定は、日本標準時で行う。
- 同じ定期実行は、同じ日の同じ時刻に、1 回だけ実行される。判定の処理が重なって動いても、重複して実行しない。
- 実行に失敗したときも、他の定期実行の判定と実行は続く。
- 定期実行の処理は、画面を開いていなくても動く。

### REQ-010: 定期実行の実行結果の記録

システムは、定期実行を行ったとき、その結果を、利用者が確認できる形で残すこと。

**受け入れ条件**

- 定期実行ごとに、最後に実行した日時と、その結果（成功、一部失敗、失敗）が分かる。
- 失敗したとき、どの機器の切り替えが失敗したかが分かる。

### REQ-011: 機器の操作と状態取得の API

システムは、機器の状態の取得と、機器の状態の変更（個別切替、一括切替）を、API として提供すること。定期実行の登録・変更・削除・一覧も、API として提供すること。画面と定期実行は、同じ API の機能を使うこと。AI などの他のシステムも、同じ API を使えること。

**受け入れ条件**

- 5 つの機器の状態と取得日時を、API で取得できる。
- 間接照明、屋内スピーカー、枕元スピーカー、玄関ドアの状態を、API で個別に変更できる。
- 5 種の一括切替を、API で実行できる。
- 定期実行の一覧、登録、変更、削除を、API で行える。
- 電灯を変更する API の要求は、状態を変えない（未実装の間）。
- 機器の状態の取得と変更は、画面からも、定期実行からも、AI からも、同じ内容で行われる。

### REQ-012: SwitchBot との連携

システムは、機器の状態の取得と操作を、SwitchBot の Web API を通して行うこと。SwitchBot の認証情報と、各機器の識別子は、設定値として持ち、画面や応答、ログに出さないこと。

**受け入れ条件**

- 間接照明、屋内スピーカー、枕元スピーカーの状態は、SwitchBot から取得した現在の値である。
- 玄関ドアの状態と電池残量は、SwitchBot から取得した現在の値である。
- 認証情報と機器の識別子は、画面、API の応答、ログに含まれない。
- SwitchBot に接続できないときや、SwitchBot がエラーを返したとき、システムはその旨を利用者に分かる形で示し、状態を推測して表示しない。

### REQ-013: 操作の記録

システムは、機器の状態の取得、状態の変更、定期実行の判定と実行について、入力された内容、判断結果、正常系ではない場合の理由をログに残すこと。

**受け入れ条件**

- 機器の状態の変更を試みたとき、対象の機器、変更後の状態、実行した主体（画面の利用者、API の利用者、定期実行）、成功か失敗か、失敗の理由がログに残る。
- 定期実行を判定したとき、対象の定期実行、実行する／しないの判断、その理由がログに残る。
- ログの 1 行は、タイムスタンプ、区分、メッセージで構成される。
- SwitchBot の認証情報、機器の識別子、セッションや API キーなどの秘密情報は、ログに含まれない。

## 認証の要否

- 画面と API は、ログイン済みの利用者だけが使えること。ROOM を割り当てられていない利用者は使えないこと。
- AI などの他のシステムは、API キーで、利用者本人として API を使えること。
- 定期実行の処理は、利用者のログインを必要としない。

## スコープ外

- 電灯の実際の制御（常に OFF 表示で、操作しても何もしない。後日の要件で扱う）。
- 屋内状態（温度・湿度）の表示（温湿度計が未導入のため。後日の要件で扱う）。
- 玄関ドアの施錠・開錠の定期実行。
- 状態の自動更新（リアルタイムの監視、一定間隔の自動再取得）。状態の取得は、画面を開いたときと、更新を指示したときに行う。
- 機器の状態の履歴の保存と表示。
- 機器の追加・削除・名称変更、SwitchBot の認証情報の画面からの設定。
- 複数の利用者・複数の部屋の管理。
- 玄関ドアの電池残量の変更（表示のみ）。
- MCP サーバへのツール追加。ROOM の設計・実装が承認されたあとに、`mcp` 側の SPEC を改訂して扱う。
