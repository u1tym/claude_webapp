# 機能: knowhow-management（ノウハウ管理）

## 目的

ログイン中の利用者が、自分専用のノウハウ（作業手順や備忘録などの記事）を、大項目・中項目の2階層で分類しながら登録・閲覧・編集・削除できるようにする。件数が増えても、キーワード検索で目的の記事を探せるようにする。

## 背景

別サーバで稼働している既存のノウハウ管理サービス（`sample/knowhow` 配下にソースコードを保管）と同等の機能を、本プロジェクトの機能の一つとして実装する。渡されたソースコードには、フロントエンドが呼び出しているキーワード検索・並び替え・ノウハウ削除のAPIが含まれておらず、これらはフロントエンドの実装から挙動を推定し、本要件で定義し直す。既存サービスのデータは、別途作成する移行スクリプトで本機能のデータベースへ取り込む。

## ユーザーストーリー

- 利用者として、ノウハウを大項目・中項目で分類して整理したい。なぜなら、件数が増えても見つけやすくしたいから。
- 利用者として、キーワードでノウハウを横断的に検索したい。なぜなら、どの分類に入れたか忘れても探し出したいから。
- 利用者として、中項目内でノウハウの並び順を入れ替えたい。なぜなら、よく使うものを上に置きたいから。
- 利用者として、不要になった大項目・中項目・ノウハウを削除したい。なぜなら、整理を保ちたいから。
- 利用者として、自分が登録した分類・ノウハウだけを扱いたい。なぜなら、他人のデータを見せたくないから。

## 用語

| 用語 | 意味 |
|------|------|
| 大項目 | 最上位の分類。名称を持つ。同一利用者の未削除の大項目内で名称が一意。 |
| 中項目 | 大項目にぶら下がる分類。名称を持つ。同一大項目内で名称が一意。 |
| ノウハウ | 中項目に属する記事。タイトル・キーワード（任意）・本文を持つ。中項目を指定せず「未分類」として登録することもできる。 |
| 表示順 | 大項目・中項目・ノウハウそれぞれが、同じ親の中で並ぶ順序を表す値。 |

## 要件

要件は EARS の意味を保ち、日本語の文で書く。画面部品、テーブル定義、API パス、HTTP ステータスなど設計は書かない。

### REQ-001

本機能を利用するとき、システムはログインを必須とし、ログイン中ユーザに本機能が割り当てられているときだけ利用を許可すること。ただし、有効な API キーを添えた要求は、その API キーの持ち主がログインしているものとして扱うこと（API キーの発行・失効は `api-key-management` が担う）。

#### 受け入れ条件

- [ ] 未ログインでは、分類・ノウハウの参照も操作もできない。
- [ ] 本機能が割り当てられていないログイン中ユーザは、参照も操作もできない。
- [ ] 論理削除済みのユーザまたは本機能では、参照も操作もできない。
- [ ] 判定は他機能の API に依存しない。
- [ ] 有効な API キーを添えた要求は、ログインしなくても、その持ち主として参照・操作できる。扱えるのは持ち主本人のデータだけである。
- [ ] 無効な API キー（存在しない、失効済み、有効期限切れ、持ち主が論理削除済み）を添えた要求は、未ログインとして扱う。
- [ ] API キーの持ち主に本機能が割り当てられていないときは、参照も操作もできない。

### REQ-002

システムは常に、ログイン中ユーザ本人が登録した大項目・中項目・ノウハウだけを参照・操作の対象とすること。他の利用者が登録したものは、参照も操作もできないこと。

#### 受け入れ条件

- [ ] 一覧・検索・詳細取得・登録・変更・削除・並び替えは、操作しているユーザ本人が登録したものだけを対象にする。
- [ ] 他ユーザが登録した大項目・中項目・ノウハウの ID を直接指定しても、参照・操作できない。

### REQ-003

ログイン中の利用者が大項目を登録するとき、システムは名称を受け付け、表示順を自動で割り当てること。

#### 受け入れ条件

- [ ] 名称を入力して大項目を登録できる。
- [ ] 名称は、空文字・空白のみは登録できない。
- [ ] 名称が、登録しようとしている利用者本人の未削除の大項目と重複するときは登録に失敗する。
- [ ] 表示順は、登録済みの未削除の大項目のうち最も大きい値の次の値になる。

### REQ-004

ログイン中の利用者が登録済みの大項目の名称を変更するとき、システムは名称を更新できること。

#### 受け入れ条件

- [ ] 大項目の名称を変更できる。
- [ ] 変更後の名称が、変更対象自身を除いた、同一利用者の未削除の大項目と重複するときは変更に失敗する。
- [ ] 存在しない、または既に論理削除済みの大項目の変更は失敗する。

### REQ-005

ログイン中の利用者が登録済みの大項目を削除するとき、システムは論理削除すること。削除した大項目に属する中項目、およびそれらの中項目に属するノウハウも合わせて論理削除すること。

#### 受け入れ条件

- [ ] 大項目を削除できる。削除後は一覧に出ない。
- [ ] 削除しても記録は残り、削除フラグが立った状態になる。
- [ ] 削除対象の大項目に属する未削除の中項目も、あわせて削除される。
- [ ] 削除対象の大項目に属していた中項目に属する未削除のノウハウも、あわせて削除される。
- [ ] 削除後、削除された大項目や中項目と同じ名称で、新たに登録できる。
- [ ] 存在しない、または既に論理削除済みの大項目の削除は失敗する。

### REQ-006

ログイン中の利用者が中項目を登録するとき、システムは所属する大項目と名称を受け付け、表示順を自動で割り当てること。

#### 受け入れ条件

- [ ] 有効な大項目を指定し、名称を入力して中項目を登録できる。
- [ ] 名称は、空文字・空白のみは登録できない。
- [ ] 指定した大項目が、存在しない、削除済み、または他ユーザのものであるときは登録に失敗する。
- [ ] 名称が、同一大項目内の未削除の中項目と重複するときは登録に失敗する。
- [ ] 表示順は、同一大項目内の登録済みの未削除の中項目のうち最も大きい値の次の値になる。

### REQ-007

ログイン中の利用者が登録済みの中項目の名称を変更するとき、システムは名称を更新できること。

#### 受け入れ条件

- [ ] 中項目の名称を変更できる。
- [ ] 変更後の名称が、変更対象自身を除いた、同一大項目内の未削除の中項目と重複するときは変更に失敗する。
- [ ] 存在しない、または既に論理削除済みの中項目の変更は失敗する。

### REQ-008

ログイン中の利用者が登録済みの中項目を削除するとき、システムは論理削除すること。削除した中項目に属するノウハウも合わせて論理削除すること。

#### 受け入れ条件

- [ ] 中項目を削除できる。削除後は一覧に出ない。
- [ ] 削除しても記録は残り、削除フラグが立った状態になる。
- [ ] 削除対象の中項目に属する未削除のノウハウも、あわせて削除される。
- [ ] 削除後、削除された中項目と同じ名称で、同一大項目内に新たに登録できる。
- [ ] 存在しない、または既に論理削除済みの中項目の削除は失敗する。

### REQ-009

システムは常に、指定された中項目に属する、削除されていないノウハウを表示順に一覧表示すること。一覧にはタイトルのみを表示し、本文は含めないこと。

#### 受け入れ条件

- [ ] 指定した中項目が有効なとき、その中項目に属する未削除のノウハウを表示順に一覧表示できる。
- [ ] 一覧の各項目にはタイトルが含まれ、本文は含まれない。
- [ ] 指定した中項目が存在しない、または削除済みのときは失敗する。

### REQ-010

ログイン中の利用者がノウハウを選んだとき、システムはタイトル・キーワード・本文を含む詳細を表示すること。

#### 受け入れ条件

- [ ] 未削除のノウハウ1件の、タイトル・キーワード・本文・所属する中項目を表示できる。
- [ ] 存在しない、または削除済みのノウハウの取得は失敗する。

### REQ-011

ログイン中の利用者がノウハウを登録するとき、システムはタイトル・本文を受け付け、キーワードと所属する中項目は任意で受け付け、表示順を自動で割り当てること。

#### 受け入れ条件

- [ ] タイトルと本文を入力してノウハウを登録できる（キーワードは任意入力）。
- [ ] 所属する中項目を指定して登録できる。指定しない場合は「未分類」として登録できる。
- [ ] タイトル・本文は、空文字・空白のみは登録できない。
- [ ] 中項目を指定する場合、それが存在しない、削除済み、または他ユーザのものであるときは登録に失敗する。
- [ ] 表示順は、同一利用者・同一所属先（中項目、または未分類）の登録済みの未削除のノウハウのうち最も大きい値の次の値になる。

### REQ-012

ログイン中の利用者が登録済みのノウハウを編集するとき、システムはタイトル・キーワード・本文・所属する中項目を更新できること。

#### 受け入れ条件

- [ ] タイトル・キーワード・本文・所属する中項目を編集できる。
- [ ] タイトル・本文の必須・空文字の扱いは登録時と同じ。
- [ ] 所属する中項目を変更する場合、変更先が存在しない、削除済み、または他ユーザのものであるときは変更に失敗する。所属先を「未分類」に変更することもできる。
- [ ] 所属先を変更した場合、表示順は変更後の所属先の中で採番し直す。
- [ ] 存在しない、または既に論理削除済みのノウハウの編集は失敗する。

### REQ-013

ログイン中の利用者が登録済みのノウハウを削除するとき、システムは論理削除すること。

#### 受け入れ条件

- [ ] ノウハウを削除できる。削除後は一覧・検索・詳細取得の対象外になる。
- [ ] 削除しても記録は残り、削除フラグが立った状態になる。
- [ ] 存在しない、または既に論理削除済みのノウハウの削除は失敗する。

### REQ-014

ログイン中の利用者が、同一の所属先（同じ中項目、または同じ未分類）に属する2件のノウハウの表示順を入れ替えるとき、システムはそれぞれの表示順を交換すること。

#### 受け入れ条件

- [ ] 隣り合う2件のノウハウを選んで、表示順を入れ替えられる。
- [ ] 指定した2件が同一利用者の所属先で一致しないときは失敗する。
- [ ] 指定した2件のいずれかが存在しない、削除済み、または他ユーザのものであるときは失敗する。

### REQ-015

ログイン中の利用者が1件以上のキーワードを指定して検索するとき、システムは所属する中項目・大項目を問わず、指定した全キーワードがタイトル・キーワード・本文のいずれかに含まれる、削除されていないノウハウを返すこと。

#### 受け入れ条件

- [ ] 1件のキーワードを指定すると、タイトル・キーワード・本文のいずれかにそのキーワードを含む未削除のノウハウが対象になる。
- [ ] 複数のキーワードを指定すると、指定した全てのキーワードについて、それぞれタイトル・キーワード・本文のいずれかに含むノウハウだけが対象になる（一部だけ一致するものは対象外）。
- [ ] 検索は大文字小文字を区別しない。
- [ ] 検索結果には、ノウハウのタイトルとともに、所属する大項目・中項目の名称がわかる情報を含む（未分類の場合はその旨がわかる）。
- [ ] 中項目・大項目を横断して検索できる。

### REQ-016

システムは、大項目・中項目・ノウハウの登録・変更・削除・並び替え・参照の試行について、入力された内容、それを元にした判断結果、正常系ではない場合の理由をログに残すこと。

#### 受け入れ条件

- [ ] 登録・変更・削除・並び替え・一覧取得・検索の試行と成否がログに残る。
- [ ] 失敗のときは内部理由がログに残る。
- [ ] セッション ID はログに出ない。

## 非機能要件

- 本機能の利用には認証を必須とする。利用可否は、ログイン中ユーザに本機能が割り当てられているかで判定する。他機能の API は使わない。他システム連携のため、`api-key-management` が発行した API キーによる認証も受け付ける。その場合の利用可否は、API キーの持ち主に本機能が割り当てられているかで判定する。
- 大項目・中項目・ノウハウは、ログイン中ユーザ本人が登録したものだけを扱う。他ユーザのデータは参照させない。
- 本機能は `portal` の Python を import しない。ログイン画面は本機能では提供しない（`portal` でログインする）。
- 操作の記録は、入力された内容、それを元にした判断結果、正常系ではない場合の理由を契機として出力する。
- ログはファイルサイズでローテーションする。上限サイズと世代数は、機能の `.env` で指定する。コードに埋め込まない。
- 失敗時に画面へ出す文言は、内部の詳細な理由を含まない。内部理由はログにだけ残す。

## 対象外

- ログイン画面、メニュー画面（`portal` が担う）
- 大項目・中項目・ノウハウの共有（他利用者への公開・閲覧許可）
- 変更履歴・バージョン管理
- 添付ファイル・画像の本文への埋め込み
- 大項目・中項目自体の並び替え（元アプリに無い機能のため、ノウハウの並び替えのみ対象とする）
- 本機能の初期登録（機能マスタへの追加と、利用者への割当はユーザ管理で行う）
- 別サーバ版からのデータ移行そのもの（移行スクリプトは本要件定義の対象外とし、別途作成する）
