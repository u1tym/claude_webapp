# 設計: knowhow-management（ノウハウ管理）

## 概要

本設計は `requirements.md` の REQ-001〜REQ-016 を満たす。ログイン中の、本機能が割り当てられた利用者が、自分専用の大項目・中項目・ノウハウを登録・変更・削除・一覧・検索・並び替えできるようにする。ログインとメニューは `portal` が担う。本機能は `public` のユーザ・セッション・システム設定・機能マスタ・メニュー割当を参照し、複製しない。業務テーブル（大項目・中項目・ノウハウ）はスキーマ `knowhow_management` に置く。操作の試行は、入力・判断結果・失敗時の内部理由を `log` フォルダへ残す。

画面毎の部品配置と画面遷移は `ui-design.md`、API のパス・要求・応答は `api-design.md`、テーブル定義と ER 図は `db-design.md` に書く。

## 構成

- フロントエンド: `src/features/knowhow-management/frontend` で Vue を起動。Vite `base` は `/portal_knowhow_management/`。nginx では dist をドキュメントルートの `features/knowhow-management/` に置き、公開 URL `/portal_knowhow_management/` へ対応付ける
- バックエンド: `src/features/knowhow-management/backend` の venv で uvicorn を起動
- API 基点: フロントの `VITE_API_KNOWHOW_MANAGEMENT_URL`
- DB: 業務テーブル（大項目・中項目・ノウハウ）はスキーマ `knowhow_management` に置く。ユーザ、セッション、システム設定、機能マスタ、メニュー割当はスキーマ `public` を直接読む
- ログ: バックエンドの `log/` へファイル出力する。テーブルには残さない
- 本機能の識別子: `knowhow-management`（機能マスタの識別子。利用可否判定に用いる）

関連ドキュメント:

- UI設計: `ui-design.md`
- DB設計: `db-design.md`
- API設計: `api-design.md`

### 状態管理

- セッション ID はフロントに保持しない。Cookie で送受信する。
- 大項目一覧・中項目一覧・ノウハウ一覧・検索結果・選択中の大項目/中項目/ノウハウ・並び替えモードの状態は画面内の状態とする。永続化しない。
- システム設定（ログイン画面 URL、メニュー画面 URL、システム共通アイコン）は API から取得して画面内の状態とする。
- 開いた直後に大項目一覧を取得する。大項目を選ぶと中項目一覧を、中項目を選ぶとノウハウ一覧を取得する。キーワード検索はキーワード確定のたびに再取得する。

### バリデーション

- 大項目・中項目の名称、ノウハウのタイトル・本文は、空文字・空白のみを送信しない。
- 並び替えは、隣接する2件のみを対象にする（一覧の並び順で隣り合う項目同士）。
- 失敗時は、内部理由が分からない一文のメッセージだけを示す。

### API クライアント

- 基点 URL: `import.meta.env.VITE_API_KNOWHOW_MANAGEMENT_URL`
- API ホストをコードに直書きしない
- 呼び出し時は Cookie を含める（credentials）
- エンドポイントの契約は `api-design.md`

### 業務ロジック

- すべての操作はログイン必須かつ、ログイン中ユーザに識別子 `knowhow-management` の機能が割り当てられていること。論理削除済みのユーザまたは本機能は許可しない。
- 一覧・検索・単件取得・登録・変更・削除・並び替えは、常にログイン中ユーザ自身の `user_id` で絞り込む。他ユーザの行は対象にしない（存在しないものとして扱う）。
- 大項目名の一意性は、同一 `user_id` の未削除の大項目の中でだけ判定する。中項目名の一意性は、同一大項目内の未削除の中項目の中でだけ判定する。いずれも登録時・変更時に重複があれば失敗する（変更時は対象自身を除く）。
- 大項目の削除は、対象と、その下の未削除の中項目、さらにその下の未削除のノウハウを、まとめて論理削除する（1つの操作として扱う）。中項目の削除は、対象と、その下の未削除のノウハウをまとめて論理削除する。
- 表示順は、大項目は同一ユーザの未削除大項目内、中項目は同一大項目内の未削除中項目内、ノウハウは同一ユーザ・同一所属先（中項目、または未分類）の未削除ノウハウ内で、それぞれ最大値+1を採番する。ノウハウの所属先を変更したときは、変更後の所属先で表示順を再採番する。
- ノウハウの並び替えは、指定された2件のノウハウが、いずれも操作者本人の未削除の行であり、かつ同一の所属先（同じ中項目、または同じ未分類）であることを確認したうえで、表示順の値を交換する。
- ノウハウのキーワード検索は、指定された全キーワードについて、それぞれタイトル・キーワード・本文のいずれかに大文字小文字を区別せず部分一致することを条件とする（AND）。所属する中項目・大項目を問わず、ログイン中ユーザの未削除のノウハウ全体を対象にする。検索結果には、所属する大項目・中項目の名称（未分類の場合はその旨）を含める。
- 操作が試みられたとき、次を契機としてログへ出す。
  - 入力された内容（大項目名・中項目名・ノウハウのタイトル、検索キーワードなど。本文の値そのものはログに出さない）
  - それを元にした判断結果（登録・変更・削除・並び替えの成功、一覧・検索の件数）
  - 正常系ではない場合の理由（名称重複、対象なし、入力不正、未ログイン、権限なし）
- ログの1行はタイムスタンプ、区分、メッセージの順とする。区分は INF（要求受付・成功）、WRN（想定内の失敗）、ERR（想定外）、DBG（調査用）とする。
- ログの出力先は作業ディレクトリの `log/`。ファイルサイズでローテーションする。上限サイズは `LOG_MAX_BYTES`、世代数は `LOG_BACKUP_COUNT`。いずれも `.env` から読む。
- セッションの有効期間は `SESSION_TIMEOUT_MINUTES` 分。期限切れは未ログインとする。セッションの作成と破棄は本機能では行わない。
- 画面へ返す失敗は、内部理由を含まない一文とする。内部理由はログにだけ残す。
- システム設定（ログイン画面 URL、メニュー画面 URL、システム共通アイコン）は `public` から読む。未ログインでもログイン画面 URL は取得できるようにする（未ログイン時の誘導に使う）。

### データアクセス

テーブル定義は `db-design.md`。ここにはアクセス関数の役割だけを書く。

| 対象 | 役割 |
|------|------|
| ユーザ | ID による取得（認証・認可）。業務データとしては更新しない |
| セッション | 参照。作成と破棄はしない。期限切れの扱いは未ログイン |
| システム設定 | キーによる取得 |
| 機能マスタ | 識別子による取得（本機能の利用可否）。更新しない |
| メニュー割当 | 指定ユーザに指定機能があるかの確認 |
| 大項目 | 本人の未削除行の挿入・名称変更・論理削除（子要素連鎖含む）・一覧・名称重複確認 |
| 中項目 | 本人の未削除行の挿入・名称変更・論理削除（子要素連鎖含む）・一覧・名称重複確認 |
| ノウハウ | 本人の未削除行の挿入・更新・論理削除・一覧・検索・単件取得・表示順の交換 |

### 認証 / 認可

Cookie ベースのセッション認証を用いる。ログイン API は持たない。`portal` が発行したセッション Cookie を検証する。

- 操作 API はログイン必須かつ本機能の割当必須。未ログインまたはセッション期限切れは未ログインとして扱う。割当なしは権限なしとして扱う。フロントは未ログインならログイン画面へ誘導する。
- セッション ID は URL、レスポンス本文、`localStorage` に置かない。
- `DEBUG_USER` があるときだけ、Cookie がなくてもそのユーザ名として処理してよい。本番では空にする。その場合も、当該ユーザに本機能が割り当てられていることを判定する。
- 他機能の API を認証・利用可否判定に使わない。
