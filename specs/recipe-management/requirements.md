# recipe-management（レシピ管理）要件定義

## 概要

ログイン中の利用者が、自分専用のレシピ（メニュー名・かな・工程・工程ごとの材料と分量）を登録・閲覧・編集・削除できる機能である。材料と分量名称は、選択肢（マスタ）から選び、必要なときは、その場で追加できる。

別サーバで稼働している既存のレシピ管理サービス（`sample/recipe` 配下にソースコードを保管）と同等の機能を、本プロジェクトの機能の一つとして実装する。あわせて、既存サービスのデータを、本機能のデータベースへ移行するプログラムを提供する。移行は、ファイルへのエクスポート・インポートではなく、移行元と移行先の両方のデータベースへ同時に接続して行う。

`sample/recipe` は、利用者の概念を持たない（全員が同じレシピ・材料・分量名称を共有する）。本プロジェクトでは、業務データを利用者ごとに分ける規約のため、本機能ではレシピを利用者ごとに持つ。また、サンプルは、レシピの削除の操作を持たず、「更新」で名称を変えると、旧レシピを削除済みにして新しい識別子で作り直す。本機能は、削除の操作を追加し、更新は同じレシピを上書きする。

## 用語

| 用語 | 説明 |
|------|------|
| レシピ | 1 つの料理の作り方。メニュー名、かな、工程の並びを持つ。サンプルの「メニュー」に当たる。 |
| メニュー名・かな | レシピの名称と、その読み（ひらがな）。一覧は、かなの順に並べる。 |
| 工程 | レシピの手順 1 つ。工程番号（1 から連番）、説明、その工程で使う材料（0 件以上）を持つ。 |
| 材料 | 料理に使う食材・調味料。名前とかなを持つ。 |
| 分量名称 | 分量の言い方。接頭語（例: 「大さじ」）と接尾語（例: 「cc」）と、数量が必要かどうかを持つ。接頭語か接尾語のどちらかは空でない。例: 「大さじ」（数量あり）、「少々」（数量なし）、「g」（接尾語、数量あり）。 |
| 数量 | 分量名称が「数量あり」のときに、材料ごとに入力する値（例: 「1」「1/2」）。文字列として扱う。 |
| 分量の表示 | 数量ありの分量名称は「接頭語＋数量＋接尾語」（例: 「大さじ1」「200g」）、数量なしは「接頭語＋接尾語」（例: 「少々」）。 |
| 共通 | 全利用者が使える材料・分量名称。あらかじめ登録されている。利用者は変更できない。 |
| 独自 | 利用者が追加した、その利用者だけが使える材料・分量名称。 |
| 移行元 | 既存のレシピ管理サービスの DB。 |
| 移行先 | 本機能の DB。 |

## 要件一覧

### REQ-001: 利用可否の判定

本機能を利用するとき、システムはログインを必須とし、ログイン中ユーザに本機能が割り当てられているときだけ利用を許可すること。

**受け入れ条件**

- 未ログインでは、レシピ・材料・分量名称の参照も操作もできない。
- 本機能が割り当てられていないログイン中ユーザは、参照も操作もできない。
- 論理削除済みのユーザまたは本機能では、参照も操作もできない。
- 判定は他機能の API に依存しない。

### REQ-002: 本人のデータだけを扱う

システムは常に、ログイン中ユーザ本人が登録したレシピ・独自の材料・独自の分量名称と、全利用者共通の材料・分量名称だけを、参照・操作の対象とすること。他の利用者が登録したものは、参照も操作もできないこと。

**受け入れ条件**

- 一覧・詳細取得・登録・編集・削除は、操作しているユーザ本人が登録したレシピだけを対象にする。
- 他ユーザのレシピの識別子を直接指定しても、参照・操作できない。
- 材料・分量名称の一覧には、共通のものと、本人が追加した独自のものだけが出る。他ユーザの独自のものは出ず、レシピにも指定できない。
- 共通の材料・分量名称は、全員が参照できるが、変更・削除はできない。

### REQ-003: レシピ一覧

ログイン中の利用者がレシピ一覧を表示するとき、システムは本人の、削除されていないレシピを、かなの順に表示すること。

**受け入れ条件**

- 一覧の各項目に、メニュー名とかなを表示する。
- 並び順は、かなの昇順。かなが同じときは、登録の古い順。
- 削除済みのレシピは表示しない。
- 一覧から、レシピを選んで、詳細を表示できる。
- レシピが 1 件も無いとき、その旨を表示する。

### REQ-004: レシピ詳細

ログイン中の利用者がレシピを選んだとき、システムはメニュー名・かな・材料の一覧・工程ごとの説明と材料を表示すること。

**受け入れ条件**

- メニュー名とかなを表示する。
- 「材料一覧」として、全工程の材料を、工程の順、工程内の並びの順に、材料名と分量の表示を並べて表示する。材料が 1 件も無いレシピでは、材料一覧を表示しない。
- 工程ごとに、工程番号、説明、その工程の材料（材料名と分量の表示）を、工程番号の昇順に表示する。
- 分量の表示は、数量ありの分量名称は「接頭語＋数量＋接尾語」、数量なしの分量名称は「接頭語＋接尾語」とする。
- 存在しない、削除済み、または他ユーザのレシピの詳細取得は失敗する。

### REQ-005: レシピの登録

ログイン中の利用者がレシピを登録するとき、システムはメニュー名・かな・1 件以上の工程を受け付け、各工程には説明と 0 件以上の材料（材料・分量名称・数量）を受け付けて、レシピを登録すること。

**受け入れ条件**

- メニュー名とかなは必須で、空文字・空白のみは登録できない。
- 工程は 1 件以上必要。各工程の説明は必須で、空文字・空白のみは登録できない。
- 工程番号は、入力した順に 1 から連番で付く。工程は、追加・削除できる（ただし、最後の 1 件は削除できない）。
- 各工程に、材料を 0 件以上、追加・削除できる。材料を選んだ行には、分量名称の選択が必須である。
- 分量名称が数量ありのときは、数量が必須で、空文字・空白のみは登録できない。数量なしのときは、数量を保存しない（空にする）。
- 材料と分量名称は、共通のものと本人の独自のものから選ぶ。存在しない、または他ユーザの独自のものは指定できない。
- メニュー名が、本人の削除されていないレシピと重複するときは、登録に失敗する（既存のレシピは変わらない）。削除済みのレシピと同じ名前では登録できる。
- 材料を選んでいない行（材料が未選択）は、登録の対象にしない。
- 登録が成功したとき、登録したレシピの詳細を表示する。

### REQ-006: レシピの編集

ログイン中の利用者が登録済みのレシピを編集するとき、システムはメニュー名・かな・工程（説明と材料）を更新できること。

**受け入れ条件**

- 登録時と同じ入力項目を、現在の内容を初期値として編集できる。入力の必須・検証は登録時と同じ。
- 更新すると、そのレシピの工程と材料は、入力した内容で置き換わる。レシピの識別子は変わらない。メニュー名を変更しても、別のレシピにはならず、削除済みのレシピも増えない。
- 変更後のメニュー名が、変更対象自身を除いた、本人の削除されていないレシピと重複するときは、更新に失敗する。
- 存在しない、削除済み、または他ユーザのレシピの編集は失敗する。
- 更新が成功したとき、更新後のレシピの詳細を表示する。

### REQ-007: レシピの削除

ログイン中の利用者が登録済みのレシピを削除するとき、システムはレシピを論理削除すること。

**受け入れ条件**

- レシピを削除できる。削除は、利用者が確認した後にだけ実行される。
- 削除後は、一覧・詳細に出ない。
- 削除しても記録は残り、削除済みの状態になる。
- 削除後、削除したレシピと同じメニュー名で、新たに登録できる。
- 存在しない、既に削除済み、または他ユーザのレシピの削除は失敗する。

### REQ-008: 材料の管理

ログイン中の利用者が材料を扱うとき、システムは共通と本人の独自の材料を一覧表示し、独自の材料を追加できること。

**受け入れ条件**

- あらかじめ、共通の材料として、砂糖・塩・胡椒・醤油・みりん・酒・味噌・サラダ油・卵・牛乳・バター・豆板醤（かな付き）が登録されている。
- 材料の選択肢は、共通のものと本人の独自のものを、かなの昇順（同じなら登録の古い順）で並べ、共通か独自かがわかる。
- 名前とかなを指定して、独自の材料を追加できる。名前とかなは必須で、空文字・空白のみは追加できない。
- 追加した材料は、レシピの登録・編集の画面から追加でき、追加後に、その行の材料として選べる。
- 同じ名前の材料が、共通、または本人の独自として既にあるときは、追加に失敗する（既存の材料は変わらない）。
- 共通の材料は、追加・変更・削除の対象にならない。独自の材料の変更・削除は、本機能では提供しない。

### REQ-009: 分量名称の管理

ログイン中の利用者が分量名称を扱うとき、システムは共通と本人の独自の分量名称を一覧表示し、独自の分量名称を追加できること。

**受け入れ条件**

- あらかじめ、共通の分量名称として、「小さじ」（数量あり）・「大さじ」（数量あり）・「cc」（接尾語、数量あり）・「ひとつまみ」（数量なし）が登録されている。
- 分量名称の選択肢は、共通のものと本人の独自のものを、接頭語の昇順、同じなら接尾語の昇順、それも同じなら登録の古い順で並べる。レシピの入力では、接頭語を選び、その接頭語と組になる接尾語を選ぶ形で、分量名称を選べる。
- 接頭語、接尾語（どちらも空でもよいが、両方が空は不可）、数量が必要かどうかを指定して、独自の分量名称を追加できる。
- 追加した分量名称は、レシピの登録・編集の画面から追加でき、追加後に、その行の分量名称として選べる。
- 同じ接頭語と接尾語の組が、共通、または本人の独自として既にあるときは、追加に失敗する（既存の分量名称は変わらない）。
- 共通の分量名称は、追加・変更・削除の対象にならない。独自の分量名称の変更・削除は、本機能では提供しない。

### REQ-010: 操作の記録（ログ）

システムは、本機能の主な操作の試行について、入力された内容、それを元にした判断結果、正常系ではない場合の理由をログに残すこと。

**受け入れ条件**

- レシピ・材料・分量名称の登録・変更・削除、一覧取得、詳細取得の試行と成否がログに残る。
- 失敗のときは内部理由がログに残る。
- セッション ID、パスワード、Cookie の値はログに出ない。
- レシピの説明（工程の説明）の本文そのものはログに出さない。
- 失敗時に画面へ出す文言は、内部の詳細な理由を含まない。内部理由はログにだけ残す。

### REQ-011: 移行元・移行先への同時接続

移行プログラムを実行するとき、システムは、移行元と移行先の両方のデータベースへ同時に接続し、移行元から読み取ったデータを、直接、移行先へ書き込むこと。

**受け入れ条件**

- エクスポート用のファイルや、中間ファイルを作らずに移行できる。
- 移行元の接続情報（ホスト、ポート、データベース名、ユーザ、パスワード）は、実行時の引数または環境変数で指定できる。移行先の接続情報は、本機能の設定（`backend/.env`）を用いる。
- 移行元へは読み取りだけを行い、移行元のデータを変更・削除しない。
- 接続に失敗したときは、どちらのデータベースに失敗したかがわかるメッセージを表示して終了する。移行元・移行先のパスワードは、画面にもログにも出さない。

### REQ-012: 移行の対象と対応付け

移行プログラムは、移行元のレシピ管理サービスのデータを、指定した 1 人の利用者のデータとして、移行先へ移行すること。

**受け入れ条件**

- 移行元は利用者を持たないため、移行するデータは、すべて、実行時に指定した 1 人の利用者（ユーザ名で指定）のものとして移行する。指定した利用者が、移行先に存在しない、または論理削除済みのときは、何も移行せずに終了する。
- 移行の対象は、レシピ（メニュー名・かな・工程・工程の説明・工程ごとの材料・分量名称・数量）、材料、分量名称である。
- 移行元で削除済みのレシピは、移行しない。対象外として、一覧表示する。
- 工程番号、工程内の材料の並び、説明、数量は、移行元の値をそのまま用いる。
- 移行元の材料・分量名称は、移行先の共通の材料・分量名称と同じもの（材料は名前が同じ、分量名称は接頭語と接尾語の組が同じ）は、共通に対応付ける。同じものが無いものは、指定した利用者の独自として追加する（同じ名前・組が、その利用者の独自として既にあるときは、新しく作らず、既存のものに対応付ける）。数量が必要かどうかは、移行元の値を用い、既存のものと違うときは、既存のものを変更せず、違いを一覧表示する。
- 識別子は、移行先で新しく採番する。
- 移行元のレシピが指す材料・分量名称が、移行元に存在しないとき、その工程の材料の行だけを取り除いて移行し、一覧表示する。

### REQ-013: 移行の再実行と整合性

移行プログラムは、途中で中断しても、再度実行すれば続きから移行でき、レシピ 1 件ごとに、全データが揃ったときだけ移行先へ確定すること。

**受け入れ条件**

- レシピは、1 件ごとに、メニュー名・かな・全工程・全材料の行を、まとめて確定する。途中で失敗したレシピは、そのレシピのデータを移行先に残さない。
- 移行済みのレシピは、再実行時にスキップする。移行済みかどうかは、指定した利用者の、削除されていないレシピに、同じメニュー名があるかで判定する。スキップしたレシピは一覧表示する。
- 移行したレシピは、移行先で、工程数と材料の行の数が、移行元と一致することを確認する。一致しないときは、そのレシピを移行先に残さず、失敗として一覧表示する。
- レシピ 1 件の失敗は、ほかのレシピの移行を止めない。最後に失敗したレシピを一覧表示し、失敗があったときは、終了状態でそれがわかる。

### REQ-014: 移行の実行と結果の報告

移行プログラムは、実際に書き込む前に内容を確認でき、実行後に結果を報告すること。

**受け入れ条件**

- 実際には書き込まずに、移行の対象と件数、対象外の一覧を表示して終了する確認用の実行（ドライラン）ができる。
- 実行中は、レシピ 1 件ごとに、進捗（何件中何件目、メニュー名）を表示する。
- 実行後に、種別（レシピ・工程・材料の行・材料・分量名称）ごとに、移行した件数、スキップした件数、対象外の件数、失敗の件数と、それぞれの内訳を表示する。
- 移行手順（事前準備、実行方法、再実行、後片付け）を、README として、移行プログラムとともに提供する。

## 認証の要否

本機能の画面と操作は、すべて認証を必須とする。利用可否は、ログイン中ユーザに本機能が割り当てられているかで判定する（REQ-001）。ログイン画面とメニュー画面は本機能では提供しない（`portal` が担う）。

移行プログラムは、コマンドラインから、管理者が両方のデータベースの接続情報と移行先の利用者名を指定して実行するもので、画面のログインは介さない。

## スコープ外

- ログイン画面、メニュー画面（`portal` が担う）
- 本機能の初期登録（機能マスタへの追加と、利用者への割当はユーザ管理で行う）
- レシピの画像（サンプルでも、受け渡しの形だけで、保存は未実装）
- 独自の材料・分量名称の変更・削除
- レシピの検索・絞り込み、他の利用者との共有（サンプルに無い機能）
- 移行元で削除済みのレシピの移行
- 移行元・移行先以外のデータベースや、ファイルを経由した移行（エクスポート・インポート方式）
- 移行後の移行元データの削除
