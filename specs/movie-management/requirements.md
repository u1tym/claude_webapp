# movie-management（動画管理・視聴）要件定義

## 概要

ログイン中の利用者が、自分専用の動画を登録・整理（作品・ジャンル・プレイリスト）し、ブラウザ上で再生できる機能である。再生位置を記憶し、前回の続きから視聴できる。動画ファイルは大容量のため、再生は全体の取得完了を待たずに開始でき、任意の位置へ移動できること。

別サーバで稼働している既存の動画視聴サービス（`sample/movie` 配下にソースコードを保管）と同等の機能を、本プロジェクトの機能の一つとして実装する。あわせて、既存サービスのデータ（動画ファイルを含む）を、本機能のデータベースへ移行するプログラムを提供する。移行は、ファイルへのエクスポート・インポートではなく、移行元と移行先の両方のデータベースへ同時に接続して行う。

`sample/movie` は、API 仕様書・DB 仕様書に記載のない機能（プレイリスト、続きから視聴、動画ファイルの差し替え）までソースコードで実装されている。本要件は、ソースコードの実装を正として整理する。

## 用語

| 用語 | 説明 |
|------|------|
| 動画 | 利用者が登録する動画ファイルと、そのタイトル・説明などの付随情報の総称。 |
| 作品 | 複数話で構成される動画のまとまり。タイトルと説明を持つ。作品に属さない動画（単発動画）もある。 |
| 話数 | 作品内での動画の番号。同一作品内で重複しない。 |
| 作品内順序 | 作品内で動画を再生する順序を表す値。「次の動画」の決定に用いる。 |
| ジャンル | 動画の分類。全利用者共通のジャンルと、利用者が独自に追加したジャンルがある。1 つの動画に複数付けられる。 |
| 状態 | 動画の登録状況。「登録中」「再生可能」「エラー」がある。再生できるのは「再生可能」だけ。 |
| チャンク | 動画ファイルを一定サイズで分割した断片。データベースには分割して保管する。 |
| 再生位置 | 動画の先頭からの経過時間。 |
| 再生状態 | 利用者ごと・動画ごとの、最後に停止した再生位置、視聴完了か否か、再生回数、最終再生日時。 |
| プレイリスト | 利用者が動画を選んで並べた再生リスト。名前と説明を持つ。 |
| 続きから視聴 | 最後に再生した動画、または最後に再生したプレイリスト内の動画を、その再生位置から再開する機能。 |
| 移行元 | 既存の動画視聴サービスのデータベース。 |
| 移行先 | 本機能のデータベース。 |

## 要件一覧

### REQ-001: 利用可否の判定

本機能を利用するとき、システムはログインを必須とし、ログイン中ユーザに本機能が割り当てられているときだけ利用を許可すること。

**受け入れ条件**

- 未ログインでは、動画・作品・ジャンル・プレイリストの参照も操作もできない。
- 本機能が割り当てられていないログイン中ユーザは、参照も操作もできない。
- 論理削除済みのユーザまたは本機能では、参照も操作もできない。
- 判定は他機能の API に依存しない。

### REQ-002: 本人のデータだけを扱う

システムは常に、ログイン中ユーザ本人が登録した動画・作品・独自ジャンル・プレイリスト・再生状態だけを参照・操作の対象とすること。他の利用者が登録したものは、参照も操作もできないこと。

**受け入れ条件**

- 一覧・検索・詳細取得・登録・変更・削除・再生は、操作しているユーザ本人が登録したものだけを対象にする。
- 他ユーザの動画・作品・プレイリストの ID を直接指定しても、参照・操作できない。
- 動画ファイル（チャンク）とサムネイル画像は、ログイン中の本人だけが取得できる。URL を知っていても、未ログインまたは他ユーザでは取得できない。
- 全利用者共通のジャンルは、全員が参照できるが、変更・削除はできない。

### REQ-003: 動画の登録

ログイン中の利用者が動画を登録するとき、システムは動画ファイルとタイトルを必須とし、説明・作品・話数・話タイトル・作品内順序・ジャンル・サムネイル画像を任意で受け付けて、動画を登録すること。

**受け入れ条件**

- 動画ファイル（MP4）とタイトルを指定して登録できる。タイトルは空文字・空白のみは登録できない。
- タイトルは 500 文字以内、動画の再生時間は 1 ミリ秒以上、約 4 時間（14,400,000 ミリ秒）以下である。超える場合は登録できない。
- 動画は、既存の作品に属させる、登録時に作品を新規作成して属させる、または作品に属させない（単発動画）のいずれかを選べる。
- 作品に属させる場合、同一作品内で話数が重複するときは登録に失敗する。話数は 1 以上の整数である。
- ジャンルは、全利用者共通のジャンルと自分の独自ジャンルから、0 件以上を選べる。存在しないジャンル、または他ユーザの独自ジャンルは指定できない。
- 登録中の動画は再生できない。全データの登録が完了した時点で、再生できるようになる。
- 登録が途中で失敗したとき、その動画は再生できない状態のまま残り、利用者は削除できる。
- 動画ファイルの映像コーデックが H.265（HEVC）と判定できるときは、iPhone のブラウザで再生できない旨を警告し、登録を受け付けない。H.264 への変換方法を案内する。
- 登録の進捗（何割まで完了したか）が利用者にわかる。

### REQ-004: サムネイル画像

システムは、動画ごとに 1 枚のサムネイル画像を保持し、一覧などで表示すること。

**受け入れ条件**

- 動画の登録時にサムネイル画像を指定できる。
- 指定しなかったときは、動画の 5 秒地点（5 秒未満の動画は先頭のフレーム）から自動で生成する。
- 動画 1 件につきサムネイル画像は 1 枚である。登録し直すと置き換わる。
- サムネイル画像が無い動画は、画像が無い旨がわかる表示になる。

### REQ-005: 動画一覧・検索

ログイン中の利用者が動画一覧を表示するとき、システムは本人の動画を、絞り込み・並び替え・ページ分けして表示すること。

**受け入れ条件**

- 既定では、状態が「再生可能」の動画だけを表示する。状態を指定して、「登録中」「エラー」の動画、またはすべての状態の動画を表示できる。
- ジャンル、作品で絞り込める。
- キーワードで、動画のタイトルまたは話タイトルの部分一致検索ができる。大文字小文字は区別しない。
- 並び順は、登録日時・タイトル・最終再生日時から選べ、昇順・降順を選べる。既定は登録日時の降順。最終再生日時で並べるとき、再生したことのない動画は末尾になる。
- 一覧の各項目に、サムネイル画像、タイトル、作品名、話数・話タイトル、ジャンル、再生時間、状態、前回の再生位置と視聴完了か否かを表示する。
- 一覧は 1 ページあたり 20 件を標準とし、ページを移動できる。1 ページあたりの件数は 100 件を超えられない。
- 動画が 1 件も無いとき、その旨を表示する。

### REQ-006: 動画情報の編集

ログイン中の利用者が登録済みの動画を編集するとき、システムはタイトル・説明・作品・話数・話タイトル・作品内順序・ジャンルを更新できること。動画ファイルの内容と再生時間は、この操作では変更できないこと。

**受け入れ条件**

- タイトル・説明・所属する作品（変更・解除を含む）・話数・話タイトル・作品内順序・ジャンルを編集できる。
- ジャンルは、指定した内容で全置換される。
- タイトルの必須・空文字の扱いは登録時と同じ。
- 変更後の話数が、同一作品内の他の動画と重複するときは変更に失敗する。
- 存在しない動画の編集は失敗する。

### REQ-007: 動画ファイルの差し替え

ログイン中の利用者が登録済みの動画のファイルを差し替えるとき、システムは現在のファイルを削除し、選択した新しいファイルに置き換えること。

**受け入れ条件**

- 動画ファイルを別のファイルに差し替えられる。差し替えは、利用者が確認した後にだけ実行される。
- 差し替えると、現在のファイルは削除され、再生時間とファイル形式は新しいファイルのものになる。
- 差し替えると、その動画の再生位置と視聴完了の状態は先頭に戻る。
- 新しいファイルの登録が完了するまで、その動画は再生できない。
- 新しいファイルの映像コーデックが H.265（HEVC）と判定できるときは、登録時と同様に警告し、差し替えを受け付けない。
- タイトル・説明・作品・ジャンルなど、動画情報は差し替えでは変わらない。

### REQ-008: 動画の削除

ログイン中の利用者が登録済みの動画を削除するとき、システムは動画と、その動画に付随するデータをすべて削除すること。

**受け入れ条件**

- 動画を削除できる。削除は、利用者が確認した後にだけ実行される。
- 削除すると、動画ファイル、サムネイル画像、ジャンルとの関連、その動画の再生状態が削除される。
- 削除した動画は、プレイリストから取り除かれる。続きから視聴の対象でもなくなる。
- 登録中・エラーの動画も削除できる。
- 存在しない動画の削除は失敗する。

### REQ-009: 作品の管理

ログイン中の利用者が作品を扱うとき、システムは作品の登録・一覧表示・詳細表示を行うこと。

**受け入れ条件**

- タイトル（必須、500 文字以内）と説明（任意）を指定して、作品を登録できる。空文字・空白のみのタイトルは登録できない。
- 作品一覧を、登録日時の降順で、ページ分けして表示できる。タイトルの部分一致で検索できる。
- 作品の詳細で、その作品に属する動画を、作品内順序・話数の順に、話数・話タイトル・再生時間・状態とともに確認できる。
- 存在しない、または他ユーザの作品の詳細取得は失敗する。

### REQ-010: ジャンルの管理

ログイン中の利用者がジャンルを扱うとき、システムは全利用者共通のジャンルと自分の独自ジャンルを一覧表示し、独自ジャンルを追加できること。

**受け入れ条件**

- 全利用者共通のジャンルは、洋画・邦画・アニメ・ライブ・ドラマ・ドキュメンタリー・その他があらかじめ登録されている。
- ジャンル一覧は、共通ジャンルと本人の独自ジャンルを、表示順の昇順で表示し、共通か独自かがわかる。
- 名称（必須、100 文字以内）と表示順（0 以上、省略時は 0）を指定して、独自ジャンルを追加できる。
- 同一ユーザの独自ジャンルの中で、名称が重複するときは追加に失敗する。
- 共通ジャンルは追加・変更・削除できない。

### REQ-011: 動画の再生

ログイン中の利用者が動画を再生するとき、システムは動画全体の取得完了を待たずに再生を開始し、再生位置の移動・一時停止・早送りができること。

**受け入れ条件**

- 状態が「再生可能」の動画だけ再生できる。それ以外は再生できず、その理由がわかる。
- 動画の全体を取得し終えなくても再生を開始でき、任意の再生位置へ移動（シーク）すると、その位置から再生できる。
- 一時停止・再開、早送り、全画面表示ができる。再生の操作部は、一定時間操作がないと自動的に隠れる。
- 再生開始時に、前回の再生位置から再開するか、先頭から再生するかを選べる。前回の再生位置が動画の長さを超えているとき、および動画の末尾のとき（最後まで視聴した動画）は、先頭から再生する。
- 再生を開始するたびに、その動画の再生回数と最終再生日時が更新される。
- 動画のデコードに失敗したときや取得に失敗したときは、その旨を表示する。H.265（HEVC）が原因と考えられるときは、その旨と H.264 への変換方法を案内する。
- 再生できない状態が続いても、ほかの動画の操作はできる。

### REQ-012: 再生位置の保存

ログイン中の利用者が動画を視聴しているとき、システムは再生位置と視聴完了の状態を保存すること。

**受け入れ条件**

- 一時停止したとき、再生位置を移動したとき、ほかの画面へ移動したとき、および再生中は一定間隔で、再生位置が保存される。
- 最後まで視聴したとき、視聴完了として保存される。
- 保存できる再生位置は、動画の長さ以下である。範囲外の値は保存できない。
- 保存に失敗しても、再生は止まらない。
- 保存した再生位置は、次回の再開、および動画一覧の表示に使われる。

### REQ-013: 次の動画

ログイン中の利用者が動画を再生しているとき、システムは次に再生する動画を特定し、再生が終わったら次の動画へ進めること。

**受け入れ条件**

- 動画が作品に属するときは、同一作品内で、作品内順序が現在より大きい動画のうち最小のもの（状態が「再生可能」のもの）を次の動画とする。作品内順序が同じ動画は、話数（無いものは後）、登録の識別子の順で前後を決める（作品の詳細での並びと同じ）。
- 動画が作品に属さないときは、作品に属さない本人の動画のうち、登録日時が現在より新しい最も古いもの（状態が「再生可能」のもの）を次の動画とする。
- 次の動画が無いときは、その旨がわかる。
- 再生が最後まで終わったとき、次の動画があれば、次の動画の再生へ進める。
- 利用者は、再生の途中でも、次の動画へ進める。

### REQ-014: 視聴履歴

ログイン中の利用者が視聴履歴を表示するとき、システムは本人が再生したことのある動画を、最終再生日時の新しい順に表示すること。

**受け入れ条件**

- 動画のタイトル、再生位置、視聴完了か否か、動画の長さ、最終再生日時を表示する。
- 最終再生日時の降順で、ページ分けして表示する。
- 削除した動画は表示しない。
- 履歴が 1 件も無いとき、その旨を表示する。

### REQ-015: 続きから視聴

ログイン中の利用者が動画一覧を開いたとき、システムは最後に再生した動画、および最後に再生したプレイリスト内の動画を示し、その再生位置から再開できること。

**受け入れ条件**

- 最後に単独で再生した動画（タイトル・再生位置・動画の長さ）を示し、その再生位置から再生を再開できる。
- 最後に再生したプレイリスト（プレイリスト名・その中で再生していた動画・再生位置）を示し、その再生位置から再生を再開できる。
- 動画とプレイリストは、それぞれ別に扱う。
- 再生できない状態の動画や、削除された動画・プレイリストは示さない。
- 再生の履歴がまだ無いときは、何も示さない。

### REQ-016: プレイリストの管理

ログイン中の利用者がプレイリストを扱うとき、システムはプレイリストの作成・一覧表示・詳細表示・編集・削除と、含める動画の並びの更新を行うこと。

**受け入れ条件**

- 名前（必須、500 文字以内）と説明（任意）を指定して、プレイリストを作成できる。空文字・空白のみの名前は登録できない。
- プレイリスト一覧を、更新日時の降順で、ページ分けして表示できる。各項目に、名前、説明、含まれる動画の件数を表示する。
- プレイリストの詳細で、含まれる動画を並び順に表示できる。各項目に、動画のタイトル、再生時間、サムネイル画像の有無を表示する。
- プレイリストの名前と説明を編集できる。
- プレイリストに含める動画を、選び直して並びごと更新できる。含められるのは本人の動画だけである。存在しない、または他ユーザの動画を含めることはできない。
- プレイリストを削除できる。削除は、利用者が確認した後にだけ実行される。削除しても、含まれていた動画は削除されない。
- 存在しない、または他ユーザのプレイリストの参照・操作は失敗する。

### REQ-017: プレイリストの再生

ログイン中の利用者がプレイリストを再生するとき、システムはプレイリストの動画を並び順に再生し、前後の動画へ移動でき、再生位置を保存すること。

**受け入れ条件**

- プレイリストの先頭の動画から再生できる。または、最後にそのプレイリストで再生していた動画を、その再生位置から再開できる（再生位置が動画の長さ以上のときは、その動画を先頭から再生する）。
- 動画を含まないプレイリストは再生できず、その理由がわかる。
- 現在の動画の次の動画、前の動画へ移動できる。次・前が無いときは、その旨がわかり、移動の操作はできない。
- 再生が最後まで終わったとき、次の動画があれば、次の動画を先頭から再生する。
- 次の動画・前の動画への移動時は、その動画を先頭から再生する。
- プレイリスト内での再生位置は、一時停止・移動・中断のたびに保存され、続きから視聴の対象になる（REQ-015）。
- 再生できない状態の動画を含んでいるとき、その動画は再生できず、その理由がわかる。
- 動画単体の再生と同じ操作（位置の移動、一時停止、早送り、全画面表示）ができる。

### REQ-018: 操作の記録（ログ）

システムは、本機能の主な操作の試行について、入力された内容、それを元にした判断結果、正常系ではない場合の理由をログに残すこと。

**受け入れ条件**

- 動画・作品・ジャンル・プレイリストの登録・変更・削除、動画ファイルの登録・差し替え、再生開始、一覧取得、検索の試行と成否がログに残る。
- 失敗のときは内部理由がログに残る。
- セッション ID、パスワード、Cookie の値はログに出ない。
- 再生中の定期的な再生位置保存や、動画ファイルの断片ごとの取得のような高頻度の処理は、1 件ごとにはログに残さなくてよい（動画単位・再生単位でまとめて残す）。
- 失敗時に画面へ出す文言は、内部の詳細な理由を含まない。内部理由はログにだけ残す。

### REQ-019: 移行元・移行先への同時接続

移行プログラムを実行するとき、システムは、移行元と移行先の両方のデータベースへ同時に接続し、移行元から読み取ったデータを、直接、移行先へ書き込むこと。

**受け入れ条件**

- 動画ファイルのエクスポート用ファイルや、中間ファイルを作らずに移行できる。
- 移行元の接続情報（ホスト、ポート、データベース名、ユーザ、パスワード）は、実行時の引数または環境変数で指定できる。移行先の接続情報は、本機能の設定（`backend/.env`）を用いる。
- 移行元へは読み取りだけを行い、移行元のデータを変更・削除しない。
- 接続に失敗したときは、どちらのデータベースに失敗したかがわかるメッセージを表示して終了する。移行元・移行先のパスワードは、画面にもログにも出さない。

### REQ-020: 移行の対象

移行プログラムは、移行元の動画視聴サービスのデータのうち、次のものを移行先へ移行すること。

**受け入れ条件**

- 移行の対象は、動画（動画ファイルの全データを含む）、サムネイル画像、作品、ジャンル（利用者独自のもの）、動画とジャンルの関連、再生状態（再生位置・視聴完了・再生回数・最終再生日時）、プレイリスト（含める動画の並びを含む）、続きから視聴の情報である。
- 動画は、移行元で状態が「再生可能」のものだけを移行する。「登録中」「エラー」のものは移行しない（一覧に表示する）。
- 動画の話数、作品内順序、再生時間、ファイル形式、ファイルの分割の仕方（順番・各断片の範囲）は、移行元の値をそのまま用いる。
- 登録日時・更新日時・最終再生日時は、移行元の値をそのまま用いる（「次の動画」の並びと最終再生日時の並び順を保つため）。
- 移行元の全利用者共通のジャンルは、移行先の全利用者共通のジャンルへ、名称で対応付ける。移行先に同名の共通ジャンルが無いときは、そのジャンルは移行先の共通ジャンルとして追加する。
- 利用者独自のジャンルは、移行先の同じ利用者の独自ジャンルへ移行する。同名のものが既にあるときは、新規に作らず、既存のものと対応付ける。
- 移行先で新しい識別子（動画・作品・ジャンル・プレイリストなど）を採番し、移行元との対応を保ちながら、関連するデータを移行する。
- プレイリストに含まれる動画が、移行しなかった動画（対象外、または移行できなかったもの）のとき、その項目だけを取り除いて移行し、取り除いた項目を一覧表示する。
- 続きから視聴の情報が指す動画・プレイリストが移行されなかったときは、その部分を空にして移行する。

### REQ-021: 移行するユーザの決定

移行プログラムは、移行元の利用者と、移行先の利用者を、ユーザ名の一致で対応付け、対応付けできた利用者のデータだけを移行すること。

**受け入れ条件**

- 移行元の利用者名（アカウント名）と、移行先の利用者名が一致する利用者だけを対象にする。
- 移行先で論理削除済みの利用者は、対象外とする。
- 対応付けできなかった利用者のデータは移行せず、その利用者名と、移行しなかった件数（動画・作品など）を一覧表示する。
- 実行時に、利用者名を指定して、特定の利用者だけを移行できる。指定しなかったときは、対応付けできた全利用者を移行する。

### REQ-022: 移行の再実行と整合性

移行プログラムは、途中で中断しても、再度実行すれば続きから移行でき、動画 1 件ごとに、全データが揃ったときだけ移行先へ確定すること。

**受け入れ条件**

- 動画は、1 件ごとに、動画情報・全ファイルデータ・サムネイル画像・ジャンルの関連をまとめて確定する。途中で失敗した動画は、その動画のデータを移行先に残さない。
- 移行済みの動画は、再実行時にスキップする。移行済みかどうかは、同じ利用者で、タイトル・ファイルサイズ・再生時間が一致する動画が移行先にあるかで判定する。スキップした動画は一覧表示する。
- 移行した動画は、移行先で、ファイルの断片数の合計とファイルサイズの合計が、移行元と一致することを確認する。一致しないときは、その動画を移行先に残さず、失敗として一覧表示する。
- 動画 1 件の失敗は、ほかの動画の移行を止めない。最後に失敗した動画を一覧表示し、失敗があったときは、終了状態でそれがわかる。
- 動画の全ファイルデータを一度にメモリへ載せない。数 GB の動画も移行できるよう、断片単位で読み取り・書き込みする。

### REQ-023: 移行の実行と結果の報告

移行プログラムは、実際に書き込む前に内容を確認でき、実行後に結果を報告すること。

**受け入れ条件**

- 実際には書き込まずに、移行の対象と件数、対象外の一覧を表示して終了する確認用の実行（ドライラン）ができる。
- 実行中は、動画 1 件ごとに、進捗（何件中何件目、動画のタイトル）を表示する。
- 実行後に、種別（動画・サムネイル・作品・ジャンル・再生状態・プレイリストなど）ごとに、移行した件数、スキップした件数、対象外の件数と、それぞれの内訳を表示する。
- 移行手順（事前準備、実行方法、再実行、後片付け）を、README として、移行プログラムとともに提供する。

## 認証の要否

本機能の画面と操作は、すべて認証を必須とする。利用可否は、ログイン中ユーザに本機能が割り当てられているかで判定する（REQ-001）。ログイン画面とメニュー画面は本機能では提供しない（`portal` が担う）。

移行プログラムは、コマンドラインから、管理者が両方のデータベースの接続情報を指定して実行するもので、画面のログインは介さない。

## スコープ外

- ログイン画面、メニュー画面（`portal` が担う）
- 本機能の初期登録（機能マスタへの追加と、利用者への割当はユーザ管理で行う）
- サーバ側での動画の変換（エンコード）。動画は、利用者が H.264 の MP4 として用意する。
- 動画の共有（他利用者への公開・閲覧許可）
- お気に入り、字幕、再生速度の変更、ジャンル・作品の変更・削除（元サービスに無い機能）
- 移行元で状態が「登録中」「エラー」の動画の移行
- 移行元・移行先以外のデータベースや、ファイルを経由した移行（エクスポート・インポート方式）
- 移行元の認証情報（アカウントのパスワード）の移行
- 移行後の移行元データの削除
