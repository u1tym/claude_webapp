# 別サーバ版（movie）からのデータ移行

`sample/movie` で稼働している別サーバ版の動画視聴サービスから、本機能（movie-management）へデータを移行する手順。

移行元 DB と移行先 DB の **両方へ同時に接続** し、移行元から読んだデータを直接、移行先へ書き込む。動画ファイルは大容量のため、エクスポート用のファイルは作らない。動画のデータは 1 チャンク（約 4 MB）ずつ読み書きし、動画全体をメモリへ載せない。

移行元へは **読み取りしか行わない**（読み取り専用のセッションで接続する）。移行元のデータは変更・削除されない。

## 移行するもの

| 移行元 | 移行先 | 備考 |
|--------|--------|------|
| 動画（`movie.video`）とチャンク（`movie.video_chunk`） | 動画・チャンク | 状態が `ready`（再生可能）の動画だけ。`uploading` / `error` は移行せず一覧表示する |
| サムネイル | サムネイル | 動画と同時に移行する |
| 作品 | 作品 | |
| ジャンル・動画とジャンルの関連 | ジャンル・関連 | 共通ジャンルは名称で対応付け、無ければ追加する。独自ジャンルは同じ利用者の同名のものに対応付け、無ければ追加する |
| 再生状態（再生位置・視聴完了・再生回数・最終再生日時） | 再生状態 | |
| プレイリストと項目 | プレイリストと項目 | |
| 続きから視聴（`movie.playback_context`） | 続きから視聴 | |

- 動画の話数・作品内順序・再生時間・ファイル形式・チャンクの分割は、移行元の値をそのまま使う。
- 登録日時・更新日時・最終再生日時も、移行元の値をそのまま使う（単発動画の「次の動画」は登録日時順で決まるため）。
- 識別子（動画・作品・ジャンル・プレイリストなど）は、移行先で新しく採番する。
- プレイリストに含まれる動画が移行されなかったとき（登録中・エラー・失敗など）は、その項目だけを取り除いて移行し、一覧表示する。
- 続きから視聴が指す動画・プレイリストが移行されなかったときは、その部分を空にして移行する（指す先がどちらも無いときは移行しない）。

## ユーザの対応付け

移行元の `public.accounts.username` と、本プロジェクトの `public.users.username` が **一致し、移行先で論理削除されていない** 利用者のデータだけを移行する。

- 対応付けできない利用者のデータは移行せず、ユーザ名と件数（動画・作品・プレイリスト）を「ユーザ」の欄に一覧表示する。
- 移行元の利用者に対応する `public.users` は、事前にユーザ管理で作っておくこと。本機能の利用の割当（機能マスタ・メニュー割当）は、移行には不要（画面を使う段階で必要）。
- `--username` で、特定の利用者だけを移行できる（複数回指定可）。

## 前提

- 移行先の DDL を適用済みであること。

  ```bash
  cd src/features/movie-management/backend
  python sql/apply.py
  ```

- `backend` の venv が使え、`backend/.env` が移行先（本プロジェクトの DB）を指していること。
- 移行を実行する環境から、移行元 DB と移行先 DB の両方に到達できること。
- 移行元の DB ユーザには、`public.accounts` と `movie` スキーマの読み取り権限があること。

## 手順

### 1. ドライラン（書き込まずに確認する）

```bash
cd src/features/movie-management/backend
python scripts/migrate_from_movie.py --dry-run \
  --host <移行元のホスト> --port 5432 --dbname <移行元のDB名> \
  --user <移行元のユーザ> --password <移行元のパスワード>
```

移行元の接続情報は、環境変数（`MOVIE_DB_HOST` / `MOVIE_DB_PORT` / `MOVIE_DB_NAME` / `MOVIE_DB_USER` / `MOVIE_DB_PASSWORD`）でも指定できる（引数が優先）。パスワードを、コマンド履歴に残したくないときは、環境変数を使う。

何も書き込まず、移行の対象・スキップ・対象外・（移行元データの不整合による）失敗の見込みを、標準エラー出力に表示する。ドライランでは、動画のチャンクのデータは読まない。

### 2. 実行

```bash
python scripts/migrate_from_movie.py \
  --host <移行元のホスト> --port 5432 --dbname <移行元のDB名> \
  --user <移行元のユーザ> --password <移行元のパスワード>
```

一部の利用者だけを移行するとき:

```bash
python scripts/migrate_from_movie.py ... --username alice --username bob
```

実行中は、動画 1 件ごとに進捗（`[n/全体件数] ユーザ名: タイトル`）を表示する。動画は **1 件ずつ、1 つのトランザクション** で移行する。途中で失敗した動画は、移行先へ何も残らない（ロールバックされる）。1 件の失敗は、ほかの動画の移行を止めない。

### 3. 結果を確認する

終了時に、種別ごとの件数と内訳が表示される。

```
===== 結果 =====
動画: 移行 12 / スキップ 3 / 対象外 2 / 失敗 1
    [対象外] alice の動画「作成途中」(移行元ID=8) 状態=uploading
    [失敗] alice の動画「壊れた動画」(移行元ID=9): CheckViolation: ...
```

| 区分 | 意味 |
|------|------|
| 移行 | 移行先へ書き込んだ（ドライランでは「移行予定」） |
| スキップ | 移行先に既にあるため書き込まなかった（再実行時の移行済みなど） |
| 対象外 | 移行の対象ではない（状態が再生可能でない動画、ユーザが対応付けできない、指す先が移行されていない再生状態など） |
| 失敗 | 移行しようとしたが失敗した。理由が併記される |

- 失敗が 1 件でもあると、終了コードは `1`（接続できないときは `2`、正常終了は `0`）。
- 操作の記録（開始・動画ごとの成否・終了）は、`backend/log/` にも残る。パスワードは出力しない。
- 移行した動画は、チャンク数とバイト長の合計が、移行元と一致することを確認したうえで確定している。

### 4. 再実行

途中で止まった場合や、失敗の原因（移行元のデータなど）を直した後は、**同じコマンドをもう一度実行すればよい**。

- 移行済みの動画は、同じ利用者で **タイトル・ファイルサイズ・再生時間が一致する動画** が移行先にあるかで判定し、スキップする。
- 作品は同じ利用者・同じタイトル、プレイリストは同じ利用者・同じ名前で判定する（同名が複数あるときは、識別子の順に 1 つずつ対応付ける）。
- 再生状態と続きから視聴は、移行先に既にあるときは **上書きしない**（移行先で視聴が進んでいる可能性があるため）。
- 移行先の動画のタイトルなどを移行後に変更していないこと。変更したときは、再実行で移行済みと判定できず、二重に移行される。再実行するときは、そのような動画がないかを、ドライランで確認する。

### 5. 後片付け

- 移行の確認が済んだら、コマンド履歴や環境変数に残した移行元のパスワードを消す。
- 移行元のデータは、この手順では削除しない。旧サービスの停止・削除は、別途判断する。

## 移行元の構造に関する注意

移行元は、`sample/movie/DB_MOVIE_SPEC.md` と `sample/movie/backend/app/models.py` の構造（スキーマ `movie`、`public.accounts`）を前提にしている。テーブルや列の構成が異なる場合は、実行時にエラーになる。エラーの内容から、どのテーブル・列が異なるかを確認すること。

## テスト

`src/features/movie-management/tests/test_migration.py`。移行元の構造を再現した一時的な DB（`tests/fixtures/source_movie.sql`）を、管理者（既定は `postgres` / `postgres`。`PG_ADMIN_USER` / `PG_ADMIN_PASSWORD` で変更可）で作り、移行先（開発用 DB）へ移行して検証する。テスト後に一時的な DB は削除する。
